## กฎถ้อยคำบนหน้าจอ

**ถ้อยคำของแอปเป็นกลาง:** แอปเป็นเครื่องมือทดสอบ LINE OA ใช้ได้กับบัญชีทุกแบบ ไม่จำเป็นต้องเป็นธุรกิจ คำอธิบาย placeholder และสถานะว่างไม่สมมติว่าเป็นร้านหรือคาเฟ่ (ไม่พูดถึงเมนู โต๊ะ หรือ "ของร้าน") ใช้คำว่าผู้ใช้ หัวข้อ ข้อมูล แทน ข้อมูลตัวอย่างใน seed (เนื้อหาของแชทและของร้านตัวอย่าง) ไม่อยู่ใต้กฎนี้

**ใช้ "ผู้ใช้" ไม่ใช้ "ลูกค้า":** คนที่ทักมาทาง LINE เรียกว่าผู้ใช้ทุกที่ที่คนอ่านได้: ถ้อยคำบนหน้าจอ (รวม `aria-label`, tooltip, toast และบรรทัดเหตุการณ์ในแชท), ข้อความที่ส่งทาง LINE, prompt ของ AI และเอกสาร ชื่อในโค้ดคงเดิม (`customer`, `customer.tapped_*` และค่าใน enum ไม่เปลี่ยน) ([ADR 0031](../adr/0031-settings-tabs-user-wording-and-neutral-prompt.md))

1. **หนึ่งสิ่งมีชื่อเดียวทุกที่** ตามอภิธานศัพท์ ถ้าต้องการคำใหม่ ให้เพิ่มในตาราง ไม่ตั้งคำพ้อง
2. **ปุ่มบอกสิ่งที่จะเกิด** เป็นคำกริยา เช่น "ส่ง", "อัปโหลด PDF", "ทดสอบการเชื่อมต่อ"
3. **พูดครั้งเดียว ประโยคเดียว** คำอธิบายไม่ซ้ำกับหัวข้อหรือสิ่งที่หน้าจอแสดงอยู่แล้ว
4. **ไทยธรรมดา** ไม่ใช้ "ดำเนินการ", "ทำการ", "ท่าน" และไม่ใส่ "กรุณา" ในที่ที่ไม่เพิ่มความหมาย
5. **ไม่มีคำลงท้าย "ค่ะ" หรือ "ครับ"** ในหน้าจอของแอดมิน
6. **ข้อความผิดพลาดบอกว่าเกิดอะไรและทำอย่างไรต่อ** อยู่ใกล้จุดที่เกิด และสิ่งที่แอดมินพิมพ์ไว้ไม่หาย
7. **ความผิดพลาดของระบบไม่ถูกแสดงเป็นความผิดของแอดมิน** เช่น "บันทึกไม่สำเร็จ ข้อมูลที่กรอกยังอยู่ ลองอีกครั้ง"
8. **สถานะไม่บอกด้วยสีอย่างเดียว** ต้องมีคำกำกับ

## คำทับศัพท์

**หลัก:** ประโยคบนหน้าจอเป็นไทยเสมอ เปลี่ยนแค่ตัวศัพท์ ศัพท์ใดที่แอดมิน LINE OA และนักพัฒนาไทยพูดและพิมพ์เป็นอังกฤษอยู่แล้ว ใช้คำอังกฤษ (หรือคำทับศัพท์ไทยถ้าคนไทยเขียนแบบนั้นจริง เช่น โมเดล อัปโหลด) แทนคำแปลที่ต้องคิดก่อนเข้าใจ คำไทยในชีวิตประจำวันคงเป็นไทย

**วิธีตัดสิน** ถามทีละข้อ
1. คำนี้เป็นชื่อในหน้าจอของ LINE หรือของผู้ให้บริการ AI ที่แอดมินต้องไปหาตามหรือไม่ ถ้าใช่ ใช้ชื่อตามนั้นตรงตัว (Channel access token, Webhook URL)
2. คนไทยที่ทำงานกับ LINE OA พูดคำนี้เป็นภาษาอะไรเวลาคุยกันเอง ถ้าพูดอังกฤษ ("กด publish", "input token") ใช้อังกฤษ ถ้าพูดไทย (แชท บันทึก ลบ ส่ง ผู้ใช้ ตั้งค่า) ใช้ไทย
3. คำไทยที่มีอยู่ต้องแปลกลับเป็นอังกฤษในหัวก่อนจึงเข้าใจหรือไม่ ถ้าใช่ (เผยแพร่, Token ขาเข้า) ใช้อังกฤษ ถ้าไม่ (คลังความรู้, ข้อความต้อนรับ) คงไทย
4. ข้อความที่ส่งถึงผู้ใช้ทาง LINE เป็นของคนทั่วไป ใช้ไทยล้วน ยกเว้นคำที่คนทั่วไปใช้อยู่แล้ว เช่น AI, แอดมิน

**ตัวพิมพ์:** sentence case คำแรกของป้าย ปุ่ม หรือหัวตารางขึ้นต้นตัวใหญ่ ("Publish rich menu", "Rich menu", "Input token") กลางประโยคเป็นตัวเล็ก ("ยังไม่ได้ publish", "รับ webhook ล่าสุด") ยกเว้นชื่อเฉพาะและชื่อช่องของ LINE ใช้ตัวพิมพ์ตามที่ LINE เขียนเสมอ (LINE Official Account, Messaging API, Channel ID, Channel secret, Channel access token, Webhook URL, Basic ID, Basic settings) และตัวย่อ (AI, PDF, OA, URL) หนึ่งแนวคิดใช้รูปเดียว ไม่สลับไทยกับอังกฤษ

**คำกริยาบนปุ่ม** เป็นอังกฤษได้เมื่อคำกริยานั้นคือศัพท์ที่ตัดสินแล้วว่าเป็นอังกฤษ ("Publish rich menu", "Publish อีกครั้ง") คำกริยาธรรมดาคงไทย ("นำ rich menu ออก", "อัปโหลด PDF", "คัดลอก")

ตารางนี้มีทั้งศัพท์ที่ใช้อังกฤษและศัพท์ที่ตัดสินแล้วว่าคงไทย คลังความรู้และขอบเขตหัวข้อคงไทยตามอภิธานศัพท์ด้านบน

| แนวคิด | ใช้บนหน้าจอ | ไม่ใช้ |
| --- | --- | --- |
| ตั้ง rich menu ให้ผู้ใช้เห็น | Publish, publish แล้ว, Publish อีกครั้ง | เผยแพร่, พับลิช |
| เอา rich menu ออกจาก OA | นำ rich menu ออก | Unpublish, ยกเลิกการเผยแพร่ |
| เมนูใต้ช่องพิมพ์ของ LINE | Rich menu (ต้นป้าย), rich menu (กลางประโยค) | ริชเมนู, เมนูลัด |
| ช่องทางที่ LINE ส่งข้อความเข้าระบบ | webhook, Webhook URL (ชื่อช่อง) | เว็บฮุก |
| ค่าจาก LINE Developers Console | Channel ID, Channel secret, Channel access token, Basic ID, Basic settings, Messaging API, channel | ไอดี, รหัสลับ, คอนโซล, ช่อง |
| หน่วยข้อความที่ AI คิดเงิน | token (กลางประโยค), Token (ต้นป้าย) | โทเค็น |

| ข้อมูลที่ระบบเชื่อมกับ LINE | credential (เฉพาะข้อความ error) | ข้อมูลรับรอง |

| ส่งไฟล์ขึ้นระบบ | อัปโหลด | upload, อัพโหลด |
| ข้อความกำหนดบทบาทของ AI | คำแนะนำสำหรับ AI | Prompt, Instruction |
| การ์ดที่ส่งเมื่อผู้ใช้เพิ่มเพื่อน | ข้อความต้อนรับ, การ์ดต้อนรับ | Welcome message, Flex message, ข้อความทักทาย |

| ทำซ้ำหลังไม่สำเร็จ | ลองอีกครั้ง, ลองใหม่ (ข้อความขาออกใช้ ส่งอีกครั้ง ตามอภิธานศัพท์) | Retry |
| ความผิดพลาดที่ระบบบันทึกไว้ | ข้อผิดพลาด | Error, เออเร่อ |

## ปุ่ม

- หนึ่งหน้าหรือหนึ่ง dialog มีปุ่มหลักไม่เกินปุ่มเดียว ยกเว้นปุ่มบันทึกของช่องในหน้าตั้งค่าตามข้อถัดไป
- หน้าตั้งค่าใช้ปุ่มแบบรองทั้งหน้า ปุ่มหลักมีเฉพาะใน dialog ยกเว้นปุ่มบันทึกของช่องที่แก้แล้วแต่ยังไม่บันทึก ซึ่งเป็นปุ่มหลักจนกว่าจะบันทึก ปุ่มบันทึกของช่องอยู่ข้างช่องเสมอ เมื่อค่ายังไม่เปลี่ยนเป็นปุ่มแบบรองที่กดไม่ได้ ช่องจึงไม่ขยับเมื่อเริ่มพิมพ์ ([ui-screens](../specs/ui-screens.md#92-โครงร่วม))
- ปุ่มที่อยู่ด้วยกันสูงเท่ากัน ปุ่มถอยอยู่ก่อน ปุ่มลงมือทำอยู่หลัง
- กดแล้วตอบสนองทันที: แสดงว่ากำลังทำงาน กดซ้ำไม่ได้ และความกว้างไม่เปลี่ยน
- ปุ่มหลักที่กดไม่ได้ต้องบอกเหตุผลข้างปุ่ม
- Dialog ยืนยันมีเฉพาะก่อนการกระทำที่ย้อนไม่ได้ เช่น ลบไฟล์จากคลังความรู้ และปุ่มทั้งสองบอกผลของตัวเอง

## ตัวเลขและเวลา

### วันที่และเวลา

กฎนี้ใช้กับหน้าจอเท่านั้น (ข้อความ, `aria-label`, tooltip, toast) API, log, ชื่อไฟล์, เอกสาร และข้อมูลทดสอบใช้ ISO-8601 ตามเดิม ทุกจุดใช้ภาษาไทย เขตเวลา `Asia/Bangkok` ชื่อเดือนย่อแบบไทย และปีเป็นพุทธศักราชทุกครั้งที่แสดงปี ไม่มีสตริง ISO ไม่มีปี ค.ศ. และไม่มีชื่อเดือนแบบเต็ม ฟังก์ชันอยู่ที่เดียวตาม [ui-screens ข้อ 8.1 และ 8.2](../specs/ui-screens.md#81-srccommoncommonlogicts)

| ใช้กับ | รูปแบบ | ตัวอย่าง | ฟังก์ชัน |
| --- | --- | --- | --- |
| เวลาข้างฟองข้อความ | ชั่วโมง:นาที 24 ชั่วโมง | `14:32` | `formatMessageTime` |
| เวลาในรายชื่อแชท | วันนี้: เวลา, เมื่อวาน: "เมื่อวาน", ภายใน 6 วัน: ชื่อวันย่อ, เก่ากว่านั้น: วันที่ (ปีอื่นเติมปี) | `14:32`, `เมื่อวาน`, `พ.`, `10 พ.ย.`, `10 พ.ย. 2568` | `formatListTime` |
| ป้ายวันในแชท | วันนี้: "วันนี้", เมื่อวาน: "เมื่อวาน", นอกนั้นวันที่ (ปีอื่นเติมปี) | `วันนี้`, `18 พ.ย.` | `formatDayChip` |
| วันและเวลาของเหตุการณ์ (แผงข้อมูลผู้ใช้, สถานะระบบ, LINE, dialog รายข้อความ) | วันที่ + เวลา ปีอื่นเติมปี | `18 พ.ย. 14:32`, `18 พ.ย. 2568 14:32` | `formatDateTime` |
| เดือน (ตัวเลือกเดือน, หัว dialog รายข้อความ) | เดือนย่อ + ปี | `พ.ย. 2569` | `formatMonthYear`, `formatMonthKey` |
| วันที่อ้างอิงที่ไม่วัดจากวันนี้ (วันที่ของตารางราคา) | วันที่พร้อมปีเสมอ | `3 พ.ย. 2569` | `formatDateKey` |

"ปีอื่น" คือปีตามเวลาไทยที่ต่างจากปีของวันนี้ ข้อความที่ขึ้นกับนาฬิกาของ browser แสดงหลัง hydration เท่านั้น (`useHydrated()` หรือหลังได้ข้อมูลจาก API) จึงไม่มี hydration mismatch

### ตัวเลข

- ตัวเลขมีจุลภาคคั่นหลักพัน ค่าใช้จ่ายเป็นดอลลาร์ทศนิยมสองตำแหน่ง
- สิ่งที่อ่านเป็นหน่วยเดียวไม่ถูกตัดข้ามบรรทัด เช่น จำนวนเงิน วันที่ และเวลา

## ข้อความไทยบนหน้าจอ

- `<html lang="th">`
- ข้อความที่ต้องอ่านไม่เล็กกว่า 14px ไม่มีอะไรเล็กกว่า 12px และช่องกรอกบนมือถือ 16px
- ระยะบรรทัดไม่ต่ำกว่า 1.5 และการตัดข้อความให้เหลือบรรทัดเดียวต้องไม่ตัดสระบนล่าง
- ชื่อปุ่มไม่ถูกตัด และไม่เกินสองบรรทัด

## น้ำเสียงของ AI ที่คุยกับผู้ใช้

แยกจากกฎหน้าจอของแอดมิน เพราะเป็นผู้ช่วยของบัญชีคุยกับผู้ใช้ รายละเอียดอยู่ใน [ai-reply](../specs/ai-reply.md)

- สุภาพ สั้น แบบแชท เป็นข้อความล้วน
- ใช้คำลงท้ายที่แอดมินเลือก เริ่มต้นที่ "ค่ะ" และใช้ชื่อ AI ตามที่ตั้งไว้ (ไม่ตั้งก็เรียกตัวเองว่าผู้ช่วย AI)
- บทบาทและเรื่องที่คุยมาจากคำแนะนำสำหรับ AI ที่แอดมินเขียน แกนของคำสั่งไม่สมมติว่าเป็นร้าน
- ไม่อ้างว่าเป็นคน และไม่เดาเมื่อไม่รู้
