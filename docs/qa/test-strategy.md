## สี่ชั้น

| ชั้น | เครื่องมือ | ทดสอบอะไร | ต้องใช้ |
| --- | --- | --- | --- |
| 1. Unit | Vitest | กฎใน `core/` และ use case ทั้งหมด ด้วย adapter ปลอม รวมถึงฟังก์ชันล้วนของหน้าจอ | ไม่ต้องใช้อะไร |

## กฎ

- **ชุดทดสอบของ port:** แต่ละ port มีชุดทดสอบหนึ่งชุด รันกับทั้งตัวปลอมและตัวจริง ทั้งคู่ต้องผ่าน เพื่อไม่ให้ตัวปลอมเพี้ยนจากของจริง
- **เวลาปลอม:** แกนกลางรับเวลาผ่าน `Clock` จึงทดสอบการรวมข้อความ, reply token หมดอายุ, cookie หมดอายุ และการขึ้นวันใหม่ของงบ โดยไม่รอจริง
- **Fixture ของ LINE:** ตัวอย่าง payload ของทุกชนิด event อยู่ใน repo ใช้ร่วมกันทุกชั้น
- **Fixture ร่วมแก้ค่าไม่ได้:** object หรือ array ระดับ module ที่หลาย test ใช้ร่วมกันห่อด้วย `deepFreeze` จาก [`test-support/deep-freeze.ts`](../../test-support/deep-freeze.ts) ซึ่งทำให้การแก้ค่าใน test ล้มทันทีด้วย `TypeError` test ที่ต้องการค่าต่างไปสร้างสำเนาก่อน (`{ ...FIXTURE, text: 'x' }` หรือ `structuredClone(FIXTURE)`) ห้ามเอา freeze ออกเพื่อให้ test ผ่าน
- **Coverage:** บังคับ 90% ของ `core/` ชั้นอื่นไม่บังคับตัวเลข
- **ไม่มี secret ใน CI:** ทุก test ใช้ stub
- **ข้อมูลไม่ปนกัน:** แต่ละ E2E ใช้ผู้ใช้คนละคนจึงรันขนานได้ ส่วน test ที่แตะค่ารวมของระบบ (เส้นที่ 3, 4, 6, 9, 14, 15) อยู่ในไฟล์ `e2e/global-state.serial.spec.ts` ซึ่งรันทีละเส้น และแอปไม่มี endpoint ล้างข้อมูล compose ตั้ง `RATE_LIMIT_SCALE` เพื่อไม่ให้ test ที่รันขนานจาก IP เดียวถูกจำกัด
- **รัน adapter test ทีละไฟล์และพร้อมกันหลายคน:** รันเฉพาะไฟล์ด้วย `pnpm exec vitest run --project adapters <path...>` (`pnpm test:adapters -- <path>` ไม่กรองไฟล์) และเมื่อหลายคนรันพร้อมกันบนเครื่องเดียว แต่ละคนใช้ฐานข้อมูลและ stub ของตัวเองด้วย `ADAPTER_TEST_DATABASE_NAME` และ `ADAPTER_TEST_STUB_URL` ตาม [project-setup ข้อ 6.7](../architecture/project-setup.md#67-vitestconfigts)
- **Stub และขั้นตอน E2E:** route ของ stub, fixture และขั้นตอนทุกเส้นอยู่ใน [stubs-and-fixtures](stubs-and-fixtures.md)
- **ไม่หน่วงเวลาตายตัว:** ใช้การรอแบบมีเงื่อนไขของ Playwright และตั้งช่วง polling กับเวลารวมข้อความให้สั้นผ่าน environment variable
- **เขตเวลา:** CI รันเป็น UTC และมี test ที่ครอบช่วงข้ามวันตามเวลาไทย
- **ห้ามข้าม ปิด หรือลบ test เพื่อให้ผ่าน**

## เส้นทาง E2E

รันที่ความกว้าง 1280 และ 390 ข้อความขาเข้าจำลองด้วยการยิง webhook ที่เซ็น signature ถูกต้อง และข้อความขาออกตรวจจากสิ่งที่ stub ของ LINE ได้รับ

| เส้น | เรื่อง | ต้องเห็น |
| --- | --- | --- |
| 1 | รับข้อความ | ผู้ใช้ขึ้นในรายชื่อพร้อมชื่อ และข้อความขึ้นในแชท รูปที่ LINE ไม่มีแล้วแสดงเหตุผลที่ดาวน์โหลดไม่สำเร็จ รูปโปรไฟล์จากทั้ง `profile.line-scdn.net` และ `sprofile.line-scdn.net` ขึ้นโดยไม่มี CSP violation |
| 2 | แอดมินตอบ | Stub ได้รับข้อความถูกต้อง และสถานะเป็นส่งแล้ว รายชื่อเรียงตามข้อความของผู้ใช้: แอดมินตอบแล้วแถวไม่ย้าย ผู้ใช้ส่งใหม่แล้วแถวขึ้นบน |
| 3 | AI ตอบแทน | เปิดสวิตช์แล้ว AI ตอบเอง ข้อความระบุผู้ส่งเป็น AI และเมื่อแอดมินตอบเอง AI ตอบแทนถูกปิดพร้อมบรรทัดเหตุการณ์ |
| 4 | Kill switch, Channel ID และโครงหน้า | ปิดแล้ว AI ไม่ตอบ และสวิตช์รายผู้ใช้กดไม่ได้ ส่วน LINE แสดง Channel ID ที่บันทึกไว้ ตรวจรูปแบบ และบันทึกพร้อมตรวจ Channel secret กับ LINE ตัวเลือกโมเดลเปิดและเลื่อนด้วยคีย์บอร์ดได้ Escape ปิดโดยค่าไม่เปลี่ยน ตัวเลือกเดือนเลือกด้วยการคลิกได้ และ document ไม่เลื่อนในหน้าตั้งค่า รายชื่อ และแชท (desktop ตรวจที่ 1535×920 ด้วย) |
| 5 | ส่งรูปและวิดีโอ | Stub ได้รับ URL ของรูปและภาพตัวอย่าง รูป WebP และ HEIC ถูกแปลงเป็น JPEG ใน browser วิดีโอ 12 MB ผ่าน PUT ของที่เก็บแบบ local ครบทุก byte และ body ที่ถูกตัดถูกปฏิเสธ |
| 6 | คลังความรู้ | อัปโหลด PDF แล้วขึ้นในตาราง และ AI ได้รับเนื้อหานั้น |
| 7 | ส่งไม่สำเร็จ | Stub ตอบ error แล้วขึ้นส่งไม่สำเร็จ และส่งอีกครั้งได้ |
| 8 | รหัสเข้าใช้ | รหัสผิดเข้าไม่ได้ รหัสถูกเข้าได้ และ API ตอบ 401 เมื่อไม่มี cookie |
| 9 | ขอบเขตหัวข้อ | แก้รายการหัวข้อทีละหัวข้อจนเหลือสองหัวข้อ (หัวข้อซ้ำถูกปฏิเสธ) เปิดขอบเขตหัวข้อ ข้อความในหัวข้อได้คำตอบของ AI ตามปกติ ข้อความนอกหัวข้อได้ข้อความปฏิเสธคงที่ที่คำลงท้ายตามคำลงท้ายที่ตั้งไว้ที่ stub ของ LINE โดยไม่มีคำขอไปโมเดลตอบแชท มีบรรทัดเหตุการณ์ แชทไม่ขึ้นรอแอดมิน และตัวนับในหน้าตั้งค่าเพิ่มหนึ่ง แล้วปิดขอบเขตหัวข้อคืน |
| 10 | ข้อความที่ตอบกลับ | ข้อความของ LINE ที่อ้างข้อความอื่นแสดงกล่องอ้างอิง และกดแล้วเลื่อนไปที่ข้อความต้นทาง |
| 11 | โน้ตของแอดมิน | โน้ตอยู่หลังโหลดหน้าใหม่ ไม่ถูกส่งให้ LINE หรือ Claude ลบได้หลังยืนยัน โน้ตที่พิมพ์ค้างไม่ติดไปผู้ใช้คนถัดไป และ dialog ลบที่เปิดใหม่ไม่แสดงข้อผิดพลาดของครั้งก่อน |
| 12 | ปุ่มพับเมนู | เมนูพับเป็นไอคอนและกางคืนได้จากปุ่มบนสุด และจำค่าไว้ |
| 13 | ข้อความเสียงขาเข้า | ข้อความเสียงจาก LINE ถูกเก็บและเล่นในแชทได้ พร้อมความยาว |
| 14 | Rich menu | Publish แล้ว stub มีเมนูที่มีรูปเป็นค่าเริ่มต้น การกด "วิธีทดสอบ", "คุยกับแอดมิน" และ "คุยกับ AI" บันทึกเป็นบรรทัดเหตุการณ์และได้ข้อความตามปุ่ม (แอดมิน: AI ปิดและรอแอดมิน, AI: คำทักทาย) นำออกแล้วไม่มีเมนูเริ่มต้น |
| 15 | การ์ดต้อนรับ | ข้อความต้อนรับที่แก้แสดงในตัวอย่าง follow event ได้การ์ดแบบ Flex ทาง reply ครั้งเดียว แชทแสดงการ์ด ปุ่มของการ์ดใช้ตัวจัดการเดียวกับ rich menu และปิดสวิตช์แล้วไม่ส่ง |
| 16 | แท็บของหน้าตั้งค่า | แท็บตาม URL ปุ่มลูกศร และย้อนกลับ ยังไม่เชื่อม LINE เปิดแท็บ LINE ช่อง LINE ที่บันทึกแล้วล็อกและเปิดด้วยปุ่มดินสอ ปุ่มบันทึกของชื่อ AI อยู่เสมอและช่องไม่ขยับ |

ค่าจำกัดความถี่เก็บในฐานข้อมูล การรัน E2E ทั้งชุดซ้ำหลายรอบบนฐานข้อมูลเดียวกันภายในหนึ่งชั่วโมง (ราวห้ารอบขึ้นไป) ชน `RATE_LIMIT_PDF_INGEST` แม้คูณด้วย `RATE_LIMIT_SCALE` ของ compose แล้ว เส้นที่ 6 จึงล้มด้วย 429 ก่อนรันต่อให้ลบและสร้างฐานข้อมูล `webchat` ใน container `db` ใหม่ (ไม่ใช่ `docker compose down -v`), `docker compose restart app` แล้ว `docker compose run --rm seed` หรือรอให้หน้าต่างหมด

ระหว่าง E2E ตรวจการเข้าถึงด้วย axe ในหน้ายินดีต้อนรับ (`access-gate.spec.ts`) หน้าแชท (`receive-message.spec.ts`) และหน้าตั้งค่า (`global-state.serial.spec.ts`) รายชื่อไฟล์ E2E และ helper อยู่ใน [stubs-and-fixtures](stubs-and-fixtures.md#74-helper-สำหรับเซ็นและส่ง)

## สิ่งที่ E2E ไม่ครอบคลุม

- พฤติกรรมของ LINE จริง เช่น การปฏิเสธ URL ของสื่อ และโควตา
- ทางอัปโหลดผ่าน Vercel Blob
- คุณภาพคำตอบของ AI
- การดึงโปรไฟล์ใหม่ของผู้ใช้ที่มีอยู่แล้ว ซึ่งต้องให้เวลาผ่านไป 24 ชั่วโมง ครอบคลุมด้วย unit test ของ `RefreshContactProfile` และชุดทดสอบของ `ContactRepository` กับ Postgres จริง

สามข้อแรกอยู่ในสคริปต์ทดสอบด้วยมือ

## ชุดคำถามวัดคุณภาพ AI

- คำถามภาษาไทย 22 ข้อ กับ PDF ตัวอย่าง ตาม [ai-prompt ข้อ 8](../specs/ai-prompt.md#8-ชุดคำถามวัดคุณภาพ-ai) แบ่งเป็น: ตอบได้จากคลังความรู้, ไม่มีในคลัง (ต้องส่งต่อแอดมิน), พยายามหลอกให้ทำนอกเรื่องหรือส่งลิงก์ และขอบเขตหัวข้อ (กลุ่ม G) รันสองรอบคือขอบเขตหัวข้อปิดและเปิด
- ตัวชี้วัดของ guardrail (attack success rate, false-positive rate, task success rate, unauthorized-action rate และภาระเพิ่มด้านเวลาและค่าใช้จ่ายของการคัดกรอง) คำนวณตาม [ai-prompt ข้อ 8.4](../specs/ai-prompt.md#84-ตัวชี้วัด) และได้มาจากการรันชุดนี้ด้วยมือเท่านั้น ไม่มี test อัตโนมัติใดสร้างหรืออ้างตัวเลขเหล่านี้
- เรียก Claude จริงและเสียเงิน
- **รันเมื่อเจ้าของงานสั่งเท่านั้น** ไม่อยู่ใน CI ไม่ผูกกับคำสั่ง test ปกติ และผู้พัฒนาไม่รันเอง
- ผลลัพธ์เก็บในโฟลเดอร์นี้พร้อมวันที่และโมเดล
- ตรรกะของสคริปต์ (`scripts/ai-eval.logic.ts`: การแบ่งกลุ่ม การตรวจคำตอบ และการคำนวณตัวชี้วัด) มี unit test ใน `e2e/ai-eval.unit.ts` ซึ่งรันในชุด `unit` (`pnpm test`) โดยไม่เรียกเครือข่ายหรือ Claude ไฟล์อยู่ใน `e2e/` เพราะชุด `unit` เก็บเฉพาะ `src/**/*.spec.ts` และ `e2e/**/*.unit.ts`
