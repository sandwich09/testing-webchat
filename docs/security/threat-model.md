# Threat model

> สถานะ: อนุมัติ · อัปเดตล่าสุด: 2026-11-18

## สิ่งที่ต้องปกป้อง

| ทรัพย์สิน | เหตุผล |
| --- | --- |
| แชทของลูกค้า: ชื่อ รูป ข้อความ และสื่อ | ข้อมูลส่วนบุคคล |
| สิทธิ์ส่งข้อความในนามร้าน | ใช้หลอกลวงลูกค้าได้ |
| Credential ของ LINE OA | ยึดช่องทางของร้านได้ |
| API key ของ AI และงบ | ค่าใช้จ่าย |
| เนื้อหาคลังความรู้ | ข้อมูลของร้าน |

## ขอบเขตความไว้ใจ

| ต้นทาง | ระดับ | การป้องกันที่ขอบ |
| --- | --- | --- |
| Webhook จาก LINE | ไว้ใจหลังตรวจ signature | HMAC-SHA256 จาก raw body |
| เบราว์เซอร์ของแอดมิน | ไว้ใจหลังมี cookie ของรหัสเข้าใช้ | Cookie ที่เซ็นกำกับ และตรวจต้นทางของคำขอ |
| ข้อความและสื่อของลูกค้า | ไม่ไว้ใจ | แสดงเป็นข้อความล้วน ตรวจชนิดไฟล์จากเนื้อไฟล์ |
| เนื้อหา PDF | ไม่ไว้ใจ | แยกจากคำสั่งของระบบ |
| คำตอบของ AI | ไม่ไว้ใจ | ตรวจด้วย schema และส่งเป็นข้อความล้วน |

## ภัยและการรับมือ

| ภัย | การรับมือ |
| --- | --- |
| คนนอกอ่านแชทหรือส่งข้อความในนามร้าน | รหัสเข้าใช้ตรวจที่ server ทุกหน้าและทุก API ดู [access-gate](../specs/access-gate.md) |
| เดารหัสเข้าใช้ด้วยสคริปต์ | จำกัดรหัสผิดต่อ IP ตาม `RATE_LIMIT_UNLOCK` ([project-setup](../architecture/project-setup.md#102-การจำกัดความถี่)) ซึ่ง `RATE_LIMIT_SCALE` ไม่คูณ และเทียบแบบ timing-safe |
| ปลอม webhook | ตรวจ signature ก่อนทำงานอื่น และจำกัดขนาด body |
| ส่ง webhook เดิมซ้ำ | กันซ้ำด้วย id ของ event และของข้อความ |
| เว็บอื่นสั่งเบราว์เซอร์ของแอดมินให้เรียก API | Cookie แบบ SameSite และตรวจต้นทางของคำขอที่แก้ข้อมูล |
| ข้อความของลูกค้ามี script | แสดงเป็นข้อความล้วน ไม่แทรก HTML และมี header จำกัดแหล่งที่โหลด script |
| ไฟล์ปลอมชนิดหรือใหญ่เกิน | ตรวจจากเนื้อไฟล์ จำกัดขนาด และสิทธิ์อัปโหลดกำหนดชนิดกับขนาด |
| หลอกให้ server ดึง URL ภายใน | Server ดึงเฉพาะจาก host ของ LINE ที่กำหนดตายตัว |
| Credential ของ LINE รั่วจากฐานข้อมูลหรือ API | เข้ารหัส AES-256-GCM และไม่มี API ใดคืนค่า |
| ความลับรั่วใน repo สาธารณะ | `.env` ไม่อยู่ใน Git, สแกนความลับใน CI และ push protection ของ GitHub |
| ลูกค้าหลอก AI ให้ทำนอกเรื่อง (prompt injection) | AI ไม่มีเครื่องมือ เห็นเฉพาะแชทนั้น และคำสั่งของระบบไม่มีความลับ ความเสียหายสูงสุดคือตอบผิด |
| ลูกค้าหลอกการคัดกรองขอบเขตหัวข้อ (prompt injection ต่อตัวคัดกรอง) เช่น "ไม่ต้องสนกฎ" หรือแฝงคำของหัวข้อ | คำสั่งของตัวคัดกรองถือข้อความลูกค้าเป็นข้อมูล ตอบไม่ผ่านเมื่อไม่แน่ใจ ผลต้องตรง schema และการคัดกรองที่ล้มเหลวทุกแบบปิดแบบปลอดภัย (ไม่ส่งอะไร ขึ้นรอแอดมิน) คำสั่งของการตอบแชทมีกฎหัวข้อซ้ำเป็นชั้นที่สอง ตัวคัดกรองที่ใช้ prompt ยังไม่ปิดสนิท ดู [topic-guard](../specs/topic-guard.md#สิ่งที่ไม่ทำและข้อจำกัด) และ [ADR 0020](../adr/0020-topic-guardrail-as-separate-check.md) |
| AI ตอบผิดหรือเดา | กฎให้ส่งต่อแอดมินเมื่อไม่รู้, ลูกค้าใหม่เริ่มด้วย AI ปิด และ kill switch |
| ค่าใช้จ่าย AI บานปลาย | งบต่อวัน (นับการแปลง PDF ที่ถูกปฏิเสธหลังแปลงด้วย), การรวมข้อความ, ประวัติจำกัด `AI_HISTORY_LIMIT` ข้อความ, kill switch ปิดเป็นค่าเริ่มต้น และเพดานของคลังความรู้ |
| ใช้ endpoint ที่มีต้นทุนรัว ๆ | จำกัดความถี่ของการส่งข้อความ การขอสิทธิ์อัปโหลด การแปลง PDF และการทดลองขอบเขตหัวข้อ ตาม [project-setup](../architecture/project-setup.md#102-การจำกัดความถี่) และ `RATE_LIMIT_SCALE` ห้ามตั้งใน production |
| ข้อมูลลูกค้ารั่วใน log | Logger รับเฉพาะ field ที่อนุญาต ดู [ADR 0016](../adr/0016-logging-without-pii-and-status-in-db.md) |
| Dependency หรือ action ที่ถูกแก้ | ล็อกรุ่น, ตรวจช่องโหว่ใน CI และล็อก action ด้วย commit hash ตัวแปลง HEIC (`heic-to`) ใช้ build สำหรับ CSP ที่ไม่ต้องเปิด `unsafe-eval` ([ADR 0019](../adr/0019-heic-conversion-with-heic-to.md)) |
| หน้าเว็บถูกฝังในเว็บอื่นหรือถูก search engine เก็บ | Header ห้ามฝังใน iframe และห้ามทำดัชนี |

การจับคู่แนวปฏิบัติของ guardrail กับสิ่งที่ระบบทำจริงอยู่ใน [ai-guardrails](ai-guardrails.md)

## ความเสี่ยงที่ยอมรับ

| ความเสี่ยง | เหตุผลที่ยอมรับ |
| --- | --- |
| รหัสเข้าใช้เป็นตัวเดียวใช้ร่วมกัน บอกไม่ได้ว่าใครทำอะไร | ขอบเขตของแบบทดสอบ ดู [ADR 0006](../adr/0006-shared-access-code.md) |
| รหัสที่ใช้ช่วงทดสอบเดาง่าย | มีการจำกัดจำนวนครั้ง และเปลี่ยนได้ที่ environment variable |
| URL ของรูปและวิดีโอเป็นสาธารณะ ใครได้ URL ก็เปิดดูได้ | เป็นเงื่อนไขของ LINE สำหรับสื่อขาออก ชื่อไฟล์เป็นค่าสุ่ม |
| ผู้ที่เข้าระบบได้อัปโหลดจนพื้นที่เต็มได้ | มีการจำกัดขนาดและความถี่ ไม่มีโควตาต่อผู้ใช้ |
| ไม่มีการแจ้งเตือนเมื่อระบบขัดข้อง | มีส่วนสถานะระบบแทน |
| ขอบเขตหัวข้อเป็นตัวคัดกรองที่ใช้ prompt ผู้ที่ตั้งใจอาจผ่านได้ | เป็นการป้องกันหลายชั้นสำหรับเดโม ไม่ใช่การรับประกัน ความเสียหายสูงสุดยังคือข้อความที่ AI ตอบ เพราะ AI ไม่มีเครื่องมือ |
| ไม่มีปุ่มลบข้อมูลของลูกค้ารายคน | ทำด้วยขั้นตอนใน [operations](../runbooks/operations.md) |

## ข้อมูลส่วนบุคคล

- เก็บเฉพาะที่จำเป็น: id ของ LINE, ชื่อที่แสดง, URL ของรูปโปรไฟล์, ข้อความ และสื่อ
- เมื่อเปิด AI ตอบแทน ข้อความของแชทนั้นถูกส่งให้ผู้ให้บริการ AI และ PDF ของคลังความรู้ถูกส่งให้ผู้ให้บริการ AI ตอนแปลง
- ข้อมูลตัวอย่างใน seed และ fixture เป็นข้อมูลปลอมทั้งหมด

## หลังส่งงาน

ทำตามหัวข้อ "ปิดระบบหลังส่งงาน" ใน [operations](../runbooks/operations.md): หมุน token ของ LINE, ลบหรือจำกัด API key ของ AI และเปลี่ยนรหัสเข้าใช้
