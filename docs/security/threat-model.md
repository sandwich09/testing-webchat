# Threat model

> สถานะ: อนุมัติ · อัปเดตล่าสุด: 2026-11-19

## สิ่งที่ต้องปกป้อง

| ทรัพย์สิน | เหตุผล |
| --- | --- |
| แชทของลูกค้า: ชื่อ รูป ข้อความ และสื่อ | ข้อมูลส่วนบุคคล |
| สิทธิ์ส่งข้อความในนามบัญชี LINE OA | ใช้หลอกลวงลูกค้าได้ |
| Credential ของ LINE OA | ยึดช่องทางของบัญชีได้ |
| API key ของ AI และงบ | ค่าใช้จ่าย |
| เนื้อหาคลังความรู้ | ข้อมูลของบัญชี |

## ขอบเขตความไว้ใจ

| ต้นทาง | ระดับ | การป้องกันที่ขอบ |
| --- | --- | --- |
| Webhook จาก LINE | ไว้ใจหลังตรวจ signature | HMAC-SHA256 จาก raw body |
| เบราว์เซอร์ของแอดมิน | ไว้ใจหลังมี cookie ของรหัสเข้าใช้ | Cookie ที่เซ็นกำกับ และตรวจต้นทางของคำขอ |
| Header `Host`, `x-forwarded-host`, `x-forwarded-proto` | ไว้ใจว่าเป็น host และ scheme ที่ browser ใช้: บน Vercel เขียนโดย proxy ของ Vercel (ยังไม่ได้ยืนยัน), ใน Docker ผู้เรียกเขียนเอง | หน้าเว็บของเว็บอื่นปลอมไม่ได้: browser ไม่ให้ตั้ง `Host` และ `X-Forwarded-*` ทำให้ต้องผ่าน CORS preflight ที่แอปไม่อนุญาต ใช้เฉพาะสร้าง origin ของคำขอเองในการตรวจต้นทาง ([ADR 0025](../adr/0025-same-origin-or-app-base-url.md)) |
| ข้อความและสื่อของลูกค้า | ไม่ไว้ใจ | แสดงเป็นข้อความล้วน ตรวจชนิดไฟล์จากเนื้อไฟล์ |
| เนื้อหา PDF | ไม่ไว้ใจ | แยกจากคำสั่งของระบบ |
| คำตอบของ AI | ไม่ไว้ใจ | ตรวจด้วย schema และส่งเป็นข้อความล้วน |

## ภัยและการรับมือ

| ภัย | การรับมือ |
| --- | --- |
| คนนอกอ่านแชทหรือส่งข้อความในนามบัญชี LINE OA | รหัสเข้าใช้ตรวจที่ server ทุกหน้าและทุก API ดู [access-gate](../specs/access-gate.md) |
| เดารหัสเข้าใช้ด้วยสคริปต์ | จำกัดรหัสผิดต่อ IP ตาม `RATE_LIMIT_UNLOCK` ([project-setup](../architecture/project-setup.md#102-การจำกัดความถี่)) ซึ่ง `RATE_LIMIT_SCALE` ไม่คูณ และเทียบแบบ timing-safe IP มาจากค่าสุดท้ายของ `x-forwarded-for` ที่ผู้เรียกปลอมไม่ได้ IPv6 นับต่อ /64 และคำขอที่ไม่มี IP นับรวมในถัง `RATE_LIMIT_UNLOCK_NO_IP` ([ADR 0022](../adr/0022-client-ip-from-last-forwarded-hop.md)) |
| คนที่เคยได้รหัสยังเข้าได้หลังเปลี่ยนรหัส | Key ของ cookie สร้างจาก `SESSION_SECRET` และ `ACCESS_CODE` การเปลี่ยนรหัสทำให้ cookie เดิมใช้ไม่ได้ ([access-gate](../specs/access-gate.md#พฤติกรรม)) |
| ปลอม webhook | ตรวจ signature ก่อนทำงานอื่น และจำกัดขนาด body |
| ส่ง webhook เดิมซ้ำ | กันซ้ำด้วย id ของ event และของข้อความ |
| เว็บอื่นสั่งเบราว์เซอร์ของแอดมินให้เรียก API | Cookie แบบ SameSite และตรวจต้นทางของคำขอที่แก้ข้อมูล: `Origin` ต้องเท่ากับ origin ของคำขอเอง (host และ scheme ที่ browser ใช้) หรือของ `APP_BASE_URL` ไม่มี `Origin` หรือ `null` ถูกปฏิเสธ ([ADR 0025](../adr/0025-same-origin-or-app-base-url.md)) แอปไม่ตอบ CORS จึงไม่มีหน้าเว็บอื่นส่ง header `X-Forwarded-*` มาเปลี่ยน origin ของคำขอเองได้ |
| ข้อความของลูกค้ามี script | แสดงเป็นข้อความล้วน ไม่แทรก HTML และมี header จำกัดแหล่งที่โหลด script |
| ไฟล์เสียงที่ไว้ใจไม่ได้จากลูกค้า | ดาวน์โหลดจาก host ของ LINE เท่านั้น (เสียงจาก `contentProvider` ภายนอกไม่ถูกดึง), ตรวจชนิดจาก byte แรก รับเฉพาะ M4A/MP4, MP3 และ AAC ADTS, จำกัด `AUDIO_MAX_BYTES`, เสิร์ฟด้วย `Content-Type` ที่ระบบตั้งเองพร้อม `X-Content-Type-Options: nosniff` และเล่นผ่าน `<audio>` เท่านั้น ไม่มีการรันหรือแปลงไฟล์บน server ไม่ถอดเสียงและไม่ส่งให้ AI |
| ไฟล์ปลอมชนิดหรือใหญ่เกิน | ตรวจจากเนื้อไฟล์ จำกัดขนาด และสิทธิ์อัปโหลดกำหนดชนิดกับขนาด |
| หลอกให้ server ดึง URL ภายใน | Server ดึงเฉพาะจาก host ของ LINE ที่กำหนดตายตัว |
| Credential ของ LINE รั่วจากฐานข้อมูลหรือ API | เข้ารหัส AES-256-GCM และไม่มี API ใดคืนค่า |
| ความลับรั่วใน repo สาธารณะ | `.env` ไม่อยู่ใน Git, สแกนความลับใน CI และ push protection ของ GitHub |
| ลูกค้าหลอก AI ให้ทำนอกเรื่อง (prompt injection) | AI ไม่มีเครื่องมือ เห็นเฉพาะแชทนั้น และคำสั่งของระบบไม่มีความลับ ความเสียหายสูงสุดคือตอบผิด |
| ข้อความของลูกค้าหรือ PDF ทำให้ AI ส่งลิงก์ (phishing) | คำตอบที่มีลิงก์ซึ่งไม่อยู่ในคลังความรู้หรือคำแนะนำสำหรับ AI ไม่ถูกส่ง แชทขึ้นรอแอดมินด้วย `ai.link_not_allowed` ([ai-prompt ข้อ 6.1](../specs/ai-prompt.md#61-ลิงก์ในคำตอบ)) ลิงก์ที่แฝงอยู่ใน PDF ถือว่าแอดมินเขียน จึงต้องอ่านข้อความที่แปลงแล้วก่อนใช้ |
| ลูกค้าหลอกการคัดกรองขอบเขตหัวข้อ (prompt injection ต่อตัวคัดกรอง) เช่น "ไม่ต้องสนกฎ" หรือแฝงคำของหัวข้อ | คำสั่งของตัวคัดกรองถือข้อความลูกค้าเป็นข้อมูล ตอบไม่ผ่านเมื่อไม่แน่ใจ ผลต้องตรง schema และการคัดกรองที่ล้มเหลวทุกแบบปิดแบบปลอดภัย (ไม่ส่งอะไร ขึ้นรอแอดมิน) คำสั่งของการตอบแชทมีกฎหัวข้อซ้ำเป็นชั้นที่สอง ตัวคัดกรองที่ใช้ prompt ยังไม่ปิดสนิท ดู [topic-guard](../specs/topic-guard.md#สิ่งที่ไม่ทำและข้อจำกัด) และ [ADR 0020](../adr/0020-topic-guardrail-as-separate-check.md) |
| AI ตอบผิดหรือเดา | กฎให้ส่งต่อแอดมินเมื่อไม่รู้, ลูกค้าใหม่เริ่มด้วย AI ปิด และ kill switch |
| ค่าใช้จ่าย AI บานปลาย | งบต่อวัน (นับการแปลง PDF ที่ถูกปฏิเสธหลังแปลงด้วย), การรวมข้อความ, ประวัติจำกัด `AI_HISTORY_LIMIT` ข้อความ, kill switch ปิดเป็นค่าเริ่มต้น และเพดานของคลังความรู้ |
| ใช้ endpoint ที่มีต้นทุนรัว ๆ | จำกัดความถี่ของการส่งข้อความ การขอสิทธิ์อัปโหลด การแปลง PDF และการทดลองขอบเขตหัวข้อ ตาม [project-setup](../architecture/project-setup.md#102-การจำกัดความถี่) และ `RATE_LIMIT_SCALE` ห้ามตั้งใน production |
| โน้ตของแอดมินรั่วไปถึงลูกค้า AI หรือ log | โน้ตอยู่ในตาราง `ContactNote` ของตัวเอง ไม่มีเส้นทางใดอ่านไปใส่ข้อความขาออก ประวัติของ AI หรือการคัดกรอง (ไม่อยู่ใน `Message` และ `toHistoryTurns` ไม่รู้จัก) log ของการเพิ่มลบมีแค่ `contactId` และ E2E เส้นที่ 11 ตรวจว่าข้อความของโน้ตไม่อยู่ในคำขอใดที่ stub ของ LINE และ Claude ได้รับ ([webchat-inbox](../specs/webchat-inbox.md#โน้ตของแอดมิน)) |
| ปลอม postback หรือกดปุ่มรัว ๆ ให้ AI ทำงานหรือส่งข้อความซ้ำ | Postback มาทาง webhook ที่ตรวจ signature เท่านั้น data ที่ไม่ใช่ `tw1:` ตามด้วยปุ่มที่รู้จักถูกทิ้ง (ไม่บันทึก ไม่ log ค่า) การกดเกิน `RATE_LIMIT_RICH_MENU_TAP` ต่อลูกค้าถูกทิ้ง และ "คุยกับ AI" ผ่าน kill switch งบต่อวัน lock และขอบเขตหัวข้อเหมือนข้อความ ข้อความคงที่ไม่เรียกโมเดล ([line-messaging](../specs/line-messaging.md#เมื่อลูกค้ากดปุ่ม)) |
| ผู้ใช้พิมพ์ข้อความที่เหมือนบรรทัดกำกับของปุ่มเพื่อหลอก AI | บรรทัดกำกับมาจาก `eventCode` ที่ระบบตั้งตอนรับ postback ไม่ได้มาจากข้อความ ข้อความที่พิมพ์เหมือนกันเป็นข้อความธรรมดา ผลมากสุดคือได้คำทักทาย |
| คนนอกเปลี่ยน rich menu หรือข้อความต้อนรับ | Publish นำออก และแก้ข้อความทำได้จากหน้าตั้งค่าหลังรหัสเข้าใช้และการตรวจต้นทางเท่านั้น รูปของเมนูและโครงของการ์ดอยู่ในโค้ด แอดมินแก้ได้แค่ข้อความ ซึ่งส่งเป็นข้อความล้วน id ของเมนูไม่ถูกส่งออกทาง API และ id ที่ใส่ใน path ของ LINE ถูกจำกัดอักขระ |
| ข้อมูลลูกค้ารั่วใน log | Logger รับเฉพาะ field ที่อนุญาต ดู [ADR 0016](../adr/0016-logging-without-pii-and-status-in-db.md) |
| Dependency หรือ action ที่ถูกแก้ | ล็อกรุ่น, ตรวจช่องโหว่ใน CI และล็อก action ด้วย commit hash ตัวแปลง HEIC (`heic-to`) ใช้ build สำหรับ CSP ที่ไม่ต้องเปิด `unsafe-eval` ([ADR 0019](../adr/0019-heic-conversion-with-heic-to.md)) |
| หน้าเว็บถูกฝังในเว็บอื่นหรือถูก search engine เก็บ | Header ห้ามฝังใน iframe และห้ามทำดัชนี |

การจับคู่แนวปฏิบัติของ guardrail กับสิ่งที่ระบบทำจริงอยู่ใน [ai-guardrails](ai-guardrails.md)

## ความเสี่ยงที่ยอมรับ

| ความเสี่ยง | เหตุผลที่ยอมรับ |
| --- | --- |
| รหัสเข้าใช้เป็นตัวเดียวใช้ร่วมกัน บอกไม่ได้ว่าใครทำอะไร | ขอบเขตของแบบทดสอบ ดู [ADR 0006](../adr/0006-shared-access-code.md) |
| รหัสที่ใช้ช่วงทดสอบเดาง่าย | มีการจำกัดจำนวนครั้ง และเปลี่ยนได้ที่ environment variable |
| URL ของรูปและวิดีโอเป็นสาธารณะ ใครได้ URL ก็เปิดดูได้ | เป็นเงื่อนไขของ LINE สำหรับสื่อขาออก ชื่อไฟล์เป็นค่าสุ่ม |
| ผู้ที่เข้าระบบได้อัปโหลดจนพื้นที่เต็มได้ | มีการจำกัดขนาดและความถี่ ไม่มีโควตาต่อผู้ใช้ |
| ไม่มีการแจ้งเตือนเมื่อระบบขัดข้อง | มีส่วนสถานะระบบแทน |
| การตรวจต้นทางรับ same-origin ของ host ใดก็ได้ที่ส่งคำขอมาถึง server: หน้าเว็บที่ใช้ DNS rebinding ชี้ชื่อของตัวเองมาที่ server จะผ่านการตรวจนี้ | Cookie ผูกกับ host ของแอป หน้าเว็บนั้นจึงไม่มี cookie และทำได้แค่ลองรหัสซึ่งถูกจำกัดความถี่เหมือนสคริปต์ทั่วไป บน Vercel คำขอถูกส่งตาม host จึงไม่ถึง deployment นี้ |
| ขอบเขตหัวข้อเป็นตัวคัดกรองที่ใช้ prompt ผู้ที่ตั้งใจอาจผ่านได้ | เป็นการป้องกันหลายชั้นสำหรับเดโม ไม่ใช่การรับประกัน ความเสียหายสูงสุดยังคือข้อความที่ AI ตอบ เพราะ AI ไม่มีเครื่องมือ |
| ไม่มีปุ่มลบข้อมูลของลูกค้ารายคน | ทำด้วยขั้นตอนใน [operations](../runbooks/operations.md) |

## ข้อมูลส่วนบุคคล

- เก็บเฉพาะที่จำเป็น: id ของ LINE, ชื่อที่แสดง, URL ของรูปโปรไฟล์, ข้อความ และสื่อ
- เมื่อเปิด AI ตอบแทน ข้อความของแชทนั้นถูกส่งให้ผู้ให้บริการ AI และ PDF ของคลังความรู้ถูกส่งให้ผู้ให้บริการ AI ตอนแปลง
- ข้อมูลตัวอย่างใน seed และ fixture เป็นข้อมูลปลอมทั้งหมด

## หลังส่งงาน

ทำตามหัวข้อ "ปิดระบบหลังส่งงาน" ใน [operations](../runbooks/operations.md): หมุน token ของ LINE, ลบหรือจำกัด API key ของ AI และเปลี่ยนรหัสเข้าใช้
