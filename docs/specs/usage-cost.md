# ค่าใช้จ่าย AI

> สถานะ: สร้างแล้ว · อัปเดตล่าสุด: 2026-11-19

## เป้าหมาย

แอดมินเห็นว่า AI ใช้ token เท่าไรและคิดเป็นเงินประมาณเท่าไร ต่อข้อความและต่อผู้ใช้ และมีเพดานที่กันค่าใช้จ่ายบานปลาย ข้อมูลนี้แสดงเฉพาะในหน้าตั้งค่า

## การบันทึก

ทุกครั้งที่เรียกโมเดล ระบบบันทึก `AiUsage` หนึ่งแถว ดู [data-model](../architecture/data-model.md)

- จำนวน token มาจากค่า usage ที่ API คืน: input, output, cache read และ cache write เมื่อเกิดการสลับโมเดลสำรองฝั่ง server ค่าระดับบนสุดของ `usage` นับเฉพาะรอบที่ตอบจริง adapter จึงรายงานผลรวมของทุกรอบใน `usage.iterations` แทน (รวมโมเดลที่ปฏิเสธก่อนสลับซึ่งถูกคิดเงินด้วย) ตาม [ai-prompt ข้อ 5.3](ai-prompt.md#53-การอ่านคำตอบของ-api)
- Token ที่โมเดลใช้คิดถูกนับเป็น output อยู่แล้วในค่าที่ API คืน
- ชื่อโมเดลมาจากคำตอบของ API (`model` ของข้อความสุดท้าย) ไม่ใช่จากค่าที่ตั้งไว้ เพราะอาจมีการสลับโมเดลสำรอง ราคาทั้งคำขอคิดด้วยราคาของโมเดลนี้
- การสลับโมเดลสำรองฝั่ง server ใช้กับ Opus 5.5 ทั้งการตอบแชทและการแปลง PDF และกับ Sonnet 5.5 เฉพาะการแปลง PDF การตอบแชทของ Sonnet 5.5 และทุกคำขอของ Haiku 5.5 ไม่ใช้ ([ai-prompt ข้อ 3](ai-prompt.md#3-โครงของ-request))
- การเรียกที่ล้มเหลวหลังจากถูกคิดเงินแล้วก็ถูกบันทึก
- การเรียกที่ส่งไปแล้วแต่ไม่ได้คำตอบก็ถูกบันทึก ตามหัวข้อถัดไป

### การเรียกที่ไม่ได้คำตอบ

คำขอที่ timeout, ถูกตัดที่เวลาสูงสุดของการเรียก (`callDeadlineMs` ใน [domain-and-ports](../architecture/domain-and-ports.md#adapter-ของ-claude)), การเชื่อมต่อหลุด หรือ stream ขาดกลางทาง อาจถึงผู้ให้บริการแล้วและอาจถูกคิดเงิน แต่ API ไม่ได้บอกจำนวน token ระบบเลือกบันทึกแบบระวังไว้ก่อน:

- adapter คืนรหัส `ai.no_response` สำหรับกรณีเหล่านี้ ส่วนการเชื่อมต่อที่ถูกปฏิเสธหรือหา host ไม่เจอ (ยังไม่ได้ส่งอะไรออกไป) คืน `ai.unavailable` เหมือนเดิม ข้อผิดพลาดที่ API ตอบกลับมาเป็น status (5xx, 429, 4xx) ไม่ถูกคิดเงินและไม่มีแถว
- ทุกการเรียกที่ได้ `ai.no_response` ถูกบันทึก `AiUsage` หนึ่งแถว: `outcome = failed`, token ทุกประเภทเป็น 0, `costUsd = 0`, `error = ai.no_response`, `model` เป็นโมเดลที่ขอ (ไม่รู้ว่า server ตอบด้วยโมเดลใด) ใช้กับการตอบแชท (`kind = reply`), การคัดกรองทั้งในแชทและในกล่องทดลอง (`kind = guard`) และการแปลง PDF (`kind = ingest`) การนับ token ของไฟล์ (count_tokens) ไม่มีค่าใช้จ่ายจึงไม่บันทึก
- ยอดเป็นศูนย์เพราะไม่รู้ราคาจริง แถวเหล่านี้จึงไม่ทำให้งบต่อวันตัดเร็วขึ้น แต่หน้าค่าใช้จ่ายแสดงจำนวนของมันต่อเดือน (`noResponseCount` ของ `GET /api/usage`) เพื่อให้รู้ว่ายอดรวมอาจต่ำกว่าบิลจริง และ [operations](../runbooks/operations.md#ค่าใช้จ่าย-ai-ไม่ตรงกับบิล) มีขั้นเทียบยอดกับ console ของผู้ให้บริการ
- หนึ่งแถวต่อการเรียกหนึ่งครั้งของ port การลองใหม่ภายใน SDK (`CLAUDE_*_MAX_RETRIES`) อยู่ในการเรียกเดียวกัน จำนวนครั้งที่ส่งจริงจึงอาจมากกว่าจำนวนแถว และ attempt ที่ timeout ก่อนที่ attempt ถัดไปจะได้คำตอบไม่ถูกนับ เพราะ adapter เห็นเฉพาะผลสุดท้าย ข้อนี้ยอมรับไว้

### โมเดลที่ไม่อยู่ในตาราง

ต้นทุนคิดจากโมเดลที่ API รายงานว่าตอบจริง (`response.model`) ซึ่งอาจเป็นโมเดลที่ server สลับไปและไม่อยู่ในตาราง ในกรณีนั้นระบบคิดราคาด้วยราคาที่สูงที่สุดในตารางของ token แต่ละประเภท เพื่อไม่ให้งบถูกประเมินต่ำ และ log เหตุการณ์ `ai.price_unknown_model` พร้อมชื่อโมเดล (`computeCost` คืน `priceKnown: false`)

หน้าจอระบุเสมอว่าเป็นราคาโดยประมาณ ณ วันที่ของตารางราคา และแสดงเป็นดอลลาร์อย่างเดียว

## หน้าจอ

ส่วน "ค่าใช้จ่าย AI" ในหน้าตั้งค่า เลือกเดือนได้

- ตารางต่อผู้ใช้: จำนวนครั้งที่ AI ตอบ, token รวม และราคาโดยประมาณ
- บรรทัดแยกสำหรับการอ่านไฟล์คลังความรู้
- บรรทัดแยกสำหรับการคัดกรองขอบเขตหัวข้อ ([topic-guard](topic-guard.md)): จำนวนครั้ง, token รวม และราคา รวมการทดลองจากหน้าตั้งค่า ข้อความที่ถูกกันไม่นับเป็นครั้งที่ AI ตอบ
- ยอดรวมของเดือน และราคาเฉลี่ยต่อข้อความที่ AI ตอบ
- เมื่อเดือนนั้นมีการเรียกที่ไม่ได้คำตอบ บรรทัด "ส่งคำขอถึง AI แล้วไม่ได้คำตอบ {n} ครั้ง ..." ใต้ราคาเฉลี่ย ([ui-copy](ui-copy.md) `settings.usage.noResponse`) แถวเหล่านี้อยู่ในรายข้อความของผู้ใช้ด้วย ผลเป็น "ไม่สำเร็จ" และ token เป็น 0
- กดที่ผู้ใช้เพื่อดูรายข้อความ: เวลา, โมเดล, token แต่ละประเภท และราคา

## งบต่อวัน

- ตั้งในหน้าตั้งค่า เป็นดอลลาร์ ค่าเริ่มต้นคือ `DEFAULT_AI_DAILY_BUDGET_USD` และตั้งได้ไม่เกิน `AI_DAILY_BUDGET_MAX_USD` ระบบนี้เป็นเดโมสำหรับทดสอบ เพดานจึงตั้งไว้ต่ำ ค่าอยู่ใน [project-setup](../architecture/project-setup.md)
- ก่อนเรียกโมเดลทุกครั้ง ระบบรวม `costUsd` ของวันนี้ตามเวลาไทย ถ้าถึงเพดานแล้ว ไม่เรียก และแชทขึ้นสถานะรอแอดมินด้วยเหตุผล "งบ AI ของวันนี้เต็ม"
- เพดานนับรวมการตอบแชท การอ่านไฟล์ และการคัดกรองขอบเขตหัวข้อ งบถูกตรวจก่อนการคัดกรอง
- การเรียกครั้งสุดท้ายก่อนถึงเพดานอาจทำให้ยอดเกินเล็กน้อย เพราะรู้ราคาหลังเรียก

## สิ่งที่ไม่ทำ

- แสดงเป็นเงินบาท
- แจ้งเตือนเมื่อใกล้ถึงเพดาน
- ดึงยอดจริงจากบิลของผู้ให้บริการ

## วิธีทดสอบ

- Unit: การคำนวณราคาของแต่ละโมเดล, การรวมยอดของวันที่ข้ามเที่ยงคืนตามเวลาไทย, การตัดเมื่อถึงเพดาน, แถว `ai.no_response` ของการตอบแชท การคัดกรอง และการแปลง PDF (`generate-ai-reply.use-case.spec.ts`, `test-topic-guard.use-case.spec.ts`, `ingest-document.use-case.spec.ts`) และ `noResponseCount` (`get-usage-report.use-case.spec.ts`)
- Adapter: ค่า usage และชื่อโมเดลถูกอ่านจากคำตอบของ stub ถูกต้อง, timeout และการตัดที่เวลาสูงสุดได้ `ai.no_response` และการเชื่อมต่อที่ถูกปฏิเสธได้ `ai.unavailable` (`claude.mapper.spec.ts`, `claude-topic-guard.adapter.spec.ts`), `countNoResponse` ในชุดทดสอบของ `UsageRepository`
