# ค่าใช้จ่าย AI

> สถานะ: สร้างแล้ว · อัปเดตล่าสุด: 2026-11-18

## เป้าหมาย

เจ้าของร้านเห็นว่า AI ใช้ token เท่าไรและคิดเป็นเงินประมาณเท่าไร ต่อข้อความและต่อลูกค้า และมีเพดานที่กันค่าใช้จ่ายบานปลาย ข้อมูลนี้แสดงเฉพาะในหน้าตั้งค่า

## การบันทึก

ทุกครั้งที่เรียกโมเดล ระบบบันทึก `AiUsage` หนึ่งแถว ดู [data-model](../architecture/data-model.md)

- จำนวน token มาจากค่า usage ที่ API คืน: input, output, อ่านจาก cache และเขียน cache เมื่อเกิดการสลับโมเดลสำรองฝั่ง server ค่าระดับบนสุดของ `usage` นับเฉพาะรอบที่ตอบจริง adapter จึงรายงานผลรวมของทุกรอบใน `usage.iterations` แทน (รวมโมเดลที่ปฏิเสธก่อนสลับซึ่งถูกคิดเงินด้วย) ตาม [ai-prompt ข้อ 5.3](ai-prompt.md#53-การอ่านคำตอบของ-api)
- Token ที่โมเดลใช้คิดถูกนับเป็น output อยู่แล้วในค่าที่ API คืน
- ชื่อโมเดลมาจากคำตอบของ API (`model` ของข้อความสุดท้าย) ไม่ใช่จากค่าที่ตั้งไว้ เพราะอาจมีการสลับโมเดลสำรอง ราคาทั้งคำขอคิดด้วยราคาของโมเดลนี้
- การสลับโมเดลสำรองฝั่ง server ใช้กับ Opus 5.5 ทั้งการตอบแชทและการแปลง PDF และกับ Sonnet 5.5 เฉพาะการแปลง PDF การตอบแชทของ Sonnet 5.5 และทุกคำขอของ Haiku 5.5 ไม่ใช้ ([ai-prompt ข้อ 3](ai-prompt.md#3-โครงของ-request))
- การเรียกที่ล้มเหลวหลังจากถูกคิดเงินแล้วก็ถูกบันทึก

### โมเดลที่ไม่อยู่ในตาราง

ต้นทุนคิดจากโมเดลที่ API รายงานว่าตอบจริง (`response.model`) ซึ่งอาจเป็นโมเดลที่ server สลับไปและไม่อยู่ในตาราง ในกรณีนั้นระบบคิดราคาด้วยราคาที่สูงที่สุดในตารางของ token แต่ละประเภท เพื่อไม่ให้งบถูกประเมินต่ำ และ log เหตุการณ์ `ai.price_unknown_model` พร้อมชื่อโมเดล (`computeCost` คืน `priceKnown: false`)

หน้าจอระบุเสมอว่าเป็นราคาโดยประมาณ ณ วันที่ของตารางราคา และแสดงเป็นดอลลาร์อย่างเดียว

## หน้าจอ

ส่วน "ค่าใช้จ่าย AI" ในหน้าตั้งค่า เลือกเดือนได้

- ตารางต่อลูกค้า: จำนวนครั้งที่ AI ตอบ, token รวม และราคาโดยประมาณ
- บรรทัดแยกสำหรับการอ่านไฟล์คลังความรู้
- บรรทัดแยกสำหรับการคัดกรองขอบเขตหัวข้อ ([topic-guard](topic-guard.md)): จำนวนครั้ง, token รวม และราคา รวมการทดลองจากหน้าตั้งค่า ข้อความที่ถูกกันไม่นับเป็นครั้งที่ AI ตอบ
- ยอดรวมของเดือน และราคาเฉลี่ยต่อข้อความที่ AI ตอบ
- กดที่ลูกค้าเพื่อดูรายข้อความ: เวลา, โมเดล, token แต่ละประเภท และราคา

## งบต่อวัน

- ตั้งในหน้าตั้งค่า เป็นดอลลาร์ ค่าเริ่มต้นคือ `DEFAULT_AI_DAILY_BUDGET_USD` และตั้งได้ไม่เกิน `AI_DAILY_BUDGET_MAX_USD` ระบบนี้เป็นเดโมสำหรับทดสอบ เพดานจึงตั้งไว้ต่ำ ค่าอยู่ใน [project-setup](../architecture/project-setup.md)
- ก่อนเรียกโมเดลทุกครั้ง ระบบรวม `costUsd` ของวันนี้ตามเวลาไทย ถ้าถึงเพดานแล้ว ไม่เรียก และแชทขึ้นสถานะรอแอดมินด้วยเหตุผล "งบ AI ของวันนี้เต็ม"
- เพดานนับรวมการตอบแชท การอ่านไฟล์ และการคัดกรองขอบเขตหัวข้อ งบถูกตรวจก่อนการคัดกรอง
- การเรียกครั้งสุดท้ายก่อนถึงเพดานอาจทำให้ยอดเกินเล็กน้อย เพราะรู้ราคาหลังเรียก

## สิ่งที่ไม่ทำ

- แสดงเป็นเงินบาท
- แจ้งเตือนเมื่อใกล้ถึงเพดาน
- ดึงยอดจริงจากบิลของผู้ให้บริการ

## วิธีทดสอบ

- Unit: การคำนวณราคาของแต่ละโมเดล, การรวมยอดของวันที่ข้ามเที่ยงคืนตามเวลาไทย, การตัดเมื่อถึงเพดาน
- Adapter: ค่า usage และชื่อโมเดลถูกอ่านจากคำตอบของ stub ถูกต้อง
