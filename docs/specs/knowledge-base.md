# คลังความรู้

> สถานะ: สร้างแล้ว · อัปเดตล่าสุด: 2026-11-19

## เป้าหมาย

แอดมินอัปโหลด PDF เช่น คู่มือ ราคา เวลาทำการ และนโยบาย แล้ว AI ใช้เนื้อหานั้นตอบลูกค้า

## วิธีทำงาน

ระบบไม่ใช้ embedding และไม่ค้นด้วยเวกเตอร์ แต่แปลง PDF เป็นข้อความครั้งเดียว แล้วแนบข้อความของทั้งคลังให้โมเดลทุกครั้งที่ตอบ เหตุผลอยู่ใน [ADR 0008](../adr/0008-knowledge-base-without-embeddings.md)

แกนกลางขอความรู้ผ่าน port `KnowledgeSource` ถ้าวันหนึ่งคลังโตเกินเพดาน สามารถเขียน adapter แบบค้นด้วยเวกเตอร์มาแทนได้โดยไม่แตะ use case

## อัปโหลด

1. รับเฉพาะ PDF ขนาดไม่เกิน `PDF_MAX_BYTES` ตรวจชนิดจากเนื้อไฟล์ และไม่เกิน `PDF_MAX_PAGES` หน้า (ตรวจหลังแปลง ดูข้อ 5)
2. คำนวณ hash ถ้าเป็นไฟล์เดิมที่มีอยู่แล้ว แจ้งและไม่ประมวลผลซ้ำ
3. สร้างรายการในสถานะ "กำลังอ่านไฟล์"
4. ส่ง PDF ให้ Claude แปลงเป็นข้อความ ผ่าน port `DocumentExtractor` ซึ่งอ่านภาษาไทยและไฟล์สแกนได้ เป็นการเรียกแบบ stream ที่รวมเป็นข้อความสุดท้าย ด้วย `AI_EXTRACT_MAX_TOKENS`, timeout `CLAUDE_EXTRACT_TIMEOUT_MS` และเวลาสูงสุดของทั้งการเรียก (`callDeadlineMs`) ที่ตัด stream ที่ยังไม่จบด้วย prompt อยู่ใน [ai-prompt](ai-prompt.md#7-prompt-ของการแปลง-pdf)
5. นับจำนวนหน้าจากตัวคั่น `=== หน้า N ===` ในข้อความที่ได้ ระบบไม่มีตัวอ่าน PDF จึงรู้จำนวนหน้าหลังแปลงเท่านั้น: **ไฟล์ที่เกิน `PDF_MAX_PAGES` หน้าถูกปฏิเสธหลังแปลงแล้ว และค่าแปลงครั้งนั้นยังถูกคิดและบันทึกในค่าใช้จ่าย AI**
6. นับ token ของข้อความด้วย endpoint นับ token ของ API ถ้ารวมกับที่มีอยู่แล้วเกินเพดานของคลัง ปฏิเสธพร้อมบอกจำนวนที่เกิน
7. บันทึกข้อความ จำนวนหน้า และจำนวน token แล้วเปลี่ยนสถานะเป็น "พร้อมใช้"
8. ไม่เก็บไฟล์ PDF ต้นฉบับ

เพดานของคลังคือ `KNOWLEDGE_CAPACITY_TOKENS` รวมทุกไฟล์ ค่าของ constant ทุกตัวอยู่ใน [project-setup](../architecture/project-setup.md#10-ค่าคงที่ของระบบ) ขั้นตอนอยู่ใน [use-cases](../architecture/use-cases.md#ingestdocument) และ route ของการอัปโหลดตั้ง `maxDuration` เป็น `KNOWLEDGE_MAX_DURATION_S` (ต้องยืนยันกับ Vercel) เวลาแย่ที่สุดของการแปลงรวมการนับ token อยู่ใต้ค่านี้ตาม [project-setup ข้อ 10.4](../architecture/project-setup.md#104-adapter-และ-route)

### ไฟล์ที่ค้าง "กำลังอ่านไฟล์"

ถ้า function ของการแปลงถูกตัด (เกินเวลาหรือ deploy ใหม่) รายการจะค้างที่ `processing` ทุกครั้งที่โหลดรายการไฟล์ (`GET /api/knowledge/documents` ซึ่งหน้าตั้งค่า poll อยู่ขณะมีไฟล์ที่กำลังอ่าน) ระบบเปลี่ยนรายการที่ `updatedAt` เก่ากว่า `KNOWLEDGE_STUCK_AFTER_MS` เป็น "ไม่สำเร็จ" ด้วยรหัส `knowledge.extract_interrupted` ด้วยคำสั่งเดียวในฐานข้อมูล ([data-model กฎของ repository ข้อ 13](../architecture/data-model.md#กฎของ-repository)) และ log `knowledge.ingest.stuck_recovered` พร้อมจำนวน แอดมินจึงกด "ลองใหม่" หรือลบได้ ค่านี้มากกว่า `KNOWLEDGE_MAX_DURATION_S` และเวลาแย่ที่สุดของการแปลง จึงไม่ตัดงานที่ยังทำอยู่

## หน้าจอ

- ตาราง: ชื่อไฟล์, จำนวนหน้า, token และสถานะ
- แถบแสดงการใช้ token เทียบกับเพดาน พร้อมตัวเลข
- เปิดอ่านข้อความที่แปลงแล้วของแต่ละไฟล์ได้ (อ่านอย่างเดียว) เพื่อตรวจว่าแปลงถูก
- ลบไฟล์ได้ มีการยืนยันก่อนลบ
- ไฟล์ที่ไม่สำเร็จมีปุ่ม "ลองใหม่" โดยต้องเลือกไฟล์อีกครั้ง เพราะระบบไม่เก็บต้นฉบับ

## กรณีผิดพลาด

| เหตุการณ์ | แอดมินเห็นอะไร |
| --- | --- |
| ไฟล์ไม่ใช่ PDF | "รองรับเฉพาะไฟล์ PDF" |
| ใหญ่เกิน `PDF_MAX_BYTES` หรือเกิน `PDF_MAX_PAGES` หน้า | บอกขีดจำกัดและขนาดหรือจำนวนหน้าของไฟล์ |
| แปลงแล้วไม่มีข้อความที่อ่านได้ | "ไม่พบข้อความที่อ่านได้ในไฟล์นี้ ใช้ไฟล์ที่มีข้อความ" |
| ไฟล์ซ้ำ | "ไฟล์นี้อยู่ในคลังความรู้แล้ว" |
| เกินเพดานของคลัง | บอกจำนวน token ที่เกิน และแนะนำให้ลบไฟล์อื่นก่อน |
| แปลงไม่สำเร็จ | สถานะ "ไม่สำเร็จ" พร้อมเหตุผล |
| ค้าง "กำลังอ่านไฟล์" นานกว่า `KNOWLEDGE_STUCK_AFTER_MS` | "แปลงไฟล์ไม่เสร็จเพราะระบบหยุดทำงานกลางคัน กด "ลองใหม่" แล้วเลือกไฟล์อีกครั้ง" |

## ต้นทุน

การแปลง PDF เรียกโมเดลและมีค่าใช้จ่าย ระบบบันทึกเป็น `AiUsage` ชนิด `ingest` ทุกครั้งที่ API ตอบ และทุกครั้งที่ส่งไปแล้วไม่ได้คำตอบ (ยอดเป็นศูนย์ ตาม [usage-cost](usage-cost.md#การเรียกที่ไม่ได้คำตอบ)) รวมไฟล์ที่ถูกปฏิเสธหลังแปลงเพราะเกินจำนวนหน้า ไม่มีข้อความ หรือเกินเพดานของคลัง และแสดงแยกบรรทัดในหน้าค่าใช้จ่าย การแปลงใช้โมเดลเดียวกับที่ตั้งไว้สำหรับแชท

คลังที่ใหญ่ขึ้นทำให้ต้นทุนต่อข้อความสูงขึ้น เพราะแนบทั้งคลังทุกครั้ง prompt caching ช่วยลดเมื่อข้อความเข้ามาถี่ แต่บัญชีที่ลูกค้าทักห่าง ๆ จะไม่ได้ประโยชน์มาก หน้าค่าใช้จ่ายแสดงตัวเลขจริง

## ความปลอดภัย

เนื้อหาจาก PDF เป็นข้อมูลที่ไว้ใจไม่ได้ ถูกแยกจากคำสั่งของระบบ และไม่ลง log

## สิ่งที่ไม่ทำ

- แก้ข้อความที่แปลงแล้วในหน้าเว็บ
- ชนิดไฟล์อื่นนอกจาก PDF
- ดาวน์โหลดไฟล์ต้นฉบับกลับ

## วิธีทดสอบ

- Unit ของ `IngestDocument`: ทุกกรณีผิดพลาด, ไฟล์ซ้ำ, เพดานของคลัง, การแปลงที่ไม่ได้คำตอบ
- Unit ของ `ListDocuments`: การคืนสภาพไฟล์ที่ค้าง และชุดทดสอบของ `KnowledgeRepository` (`failStuckProcessing` ทั้งตัวปลอมและ Postgres รวมการเรียกพร้อมกัน)
- E2E เส้นที่ 6
