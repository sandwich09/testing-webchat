# ขอบเขตหัวข้อ

> สถานะ: สร้างแล้ว · อัปเดตล่าสุด: 2026-11-19 (คำทักทายผ่านการคัดกรองตาม [ADR 0026](../adr/0026-neutral-core-prompt-and-layered-settings.md))

## เป้าหมาย

แอดมินจำกัดให้ AI คุยได้เฉพาะหัวข้อที่กำหนดเอง เช่น มุกตลกไทย มีมจากละครและซีรีส์ และมุกจากภาพยนตร์ เพื่อสาธิต guardrail ที่ตรวจแยกจาก prompt ของการตอบ เหตุผลอยู่ใน [ADR 0020](../adr/0020-topic-guardrail-as-separate-check.md)

## พฤติกรรม

1. ขอบเขตหัวข้อเปิดหรือปิดได้ที่หน้าตั้งค่า ส่วน "ขอบเขตหัวข้อ" ค่าเริ่มต้นปิด
2. เมื่อเปิด AI คุยได้เฉพาะหัวข้อในรายการ ขอบเขตหัวข้ออยู่เหนือทุก prompt: เหนือคำแนะนำสำหรับ AI และเหนือคลังความรู้ คำถามเรื่องของบัญชี เช่น เวลาทำการ ถูกกันด้วยถ้าไม่อยู่ในรายการ ไม่มีตัวเลือก "ให้ตอบเรื่องของบัญชีเสมอ" ข้อยกเว้นเดียวคือคำทักทาย ขอบคุณ และบอกลาสั้น ๆ ที่ไม่มีคำขออื่น ซึ่งผ่านเพื่อให้ผู้ช่วยแนะนำตัวได้ (ข้อ 12)
3. การตรวจเป็นการเรียกโมเดลแยกผ่าน port `TopicGuard` ด้วย `GUARD_MODEL` เสมอ ไม่ขึ้นกับโมเดลที่ตั้งไว้สำหรับตอบแชท ([domain-and-ports](../architecture/domain-and-ports.md#topicguard))
4. ลำดับการตรวจของ AI ตอบแทน: kill switch → AI ตอบแทนของลูกค้า → การติดตาม → ชนิดข้อความ → งบต่อวัน → รวมข้อความรัวและล็อก → ขอบเขตหัวข้อ → คลังความรู้และโมเดลตอบแชท การคัดกรองทำก่อนโหลดคลังความรู้และก่อนเรียกโมเดลตอบแชท ขั้นตอนอยู่ใน [use-cases](../architecture/use-cases.md#generateaireply)
5. ตัวคัดกรองได้รายการหัวข้อ ข้อความล่าสุดของลูกค้า (ข้อความรัวที่รวมแล้ว) และบริบทไม่เกิน `GUARD_CONTEXT_TURNS` turn ก่อนหน้า เพื่อตัดสินข้อความต่อเนื่อง เช่น "ขออีกมุก" ได้ถูกต้อง
6. ผ่าน: บันทึกต้นทุนของการคัดกรอง แล้วตอบตามปกติ คำสั่งระบบของการตอบได้บล็อกรายการหัวข้อและกฎ "ตอบเฉพาะหัวข้อเหล่านี้" เพิ่มเป็นชั้นที่สอง ([ai-prompt ข้อ 9.5](ai-prompt.md#95-บล็อกที่ต่อท้ายคำสั่งระบบของการตอบแชท))
7. ถูกกัน: ไม่เรียกโมเดลตอบแชท ส่งข้อความปฏิเสธให้ลูกค้าตามกฎการส่งปกติ (reply token ก่อน แล้ว push) ข้อความนี้เป็นข้อความของ AI ในแชท มีบรรทัดเหตุการณ์ `guard.blocked` แชทไม่ขึ้นรอแอดมิน และ AI ตอบแทนของลูกค้ายังเปิด
8. ชั้นที่สอง: ถ้าผ่านการคัดกรองแล้วโมเดลตอบแชทยังตัดสินว่านอกเรื่อง (เหตุผล `unsafe_or_offtopic`) ขณะขอบเขตหัวข้อเปิด ระบบทำเหมือนถูกกันในข้อ 7 ทุกอย่าง
9. ต้นทุนของการคัดกรองนับรวมในงบต่อวัน และงบถูกตรวจก่อนการคัดกรอง ([usage-cost](usage-cost.md#งบต่อวัน))
10. Kill switch ถูกตรวจซ้ำก่อนส่งข้อความปฏิเสธ เหมือนก่อนส่งคำตอบปกติ
11. ส่วนตั้งค่าแสดงจำนวนข้อความที่ถูกกันของวันนี้ตามเวลาไทย และส่วนค่าใช้จ่าย AI มีแถวแยกของการคัดกรอง
12. คำทักทาย ขอบคุณ และบอกลาสั้น ๆ ที่ไม่มีคำขอหรือคำถามอื่น (เช่น "สวัสดีค่ะ", "ขอบคุณครับ") ผ่านการคัดกรองด้วย `allowed: true` และ `matchedTopic: null` แล้วโมเดลตอบแชทตอบตามกฎการทักทาย (แนะนำตัวเมื่อยังไม่เคยแนะนำ) ข้อความที่มีคำทักทายร่วมกับคำขอ ตัดสินจากคำขอ: "สวัสดีค่ะ ขอพยากรณ์อากาศหน่อย" ถูกกันเมื่อพยากรณ์อากาศไม่อยู่ในรายการ การแยกนี้อยู่ใน prompt ของตัวคัดกรอง ([ai-prompt ข้อ 9.1](ai-prompt.md#91-คำสั่งระบบของการคัดกรอง)) และในบล็อกของชั้นที่สอง ไม่ใช่การเทียบคำในโค้ด ความล้มเหลวของการคัดกรองยังปิดแบบปลอดภัยเหมือนเดิม

ค่าที่ตั้งได้ (เก็บในแถวเดียวของ Settings ตาม [data-model](../architecture/data-model.md#settings-แถวเดียว)):

| ค่า | ข้อกำหนด |
| --- | --- |
| เปิดใช้ | boolean ค่าเริ่มต้นปิด เปิดได้เมื่อมีหัวข้ออย่างน้อยหนึ่งหัวข้อ ไม่เช่นนั้นได้ `settings.guard_topics_required` |
| หัวข้อ | 1 ถึง `GUARD_MAX_TOPICS` หัวข้อเมื่อเปิด แต่ละหัวข้อ 1 ถึง `GUARD_TOPIC_MAX_CHARS` ตัวหลังตัดช่องว่าง ห้ามซ้ำ |

ค่าของ constant ทุกตัวอยู่ใน [project-setup](../architecture/project-setup.md#101-แกนกลาง) หน้าตั้งค่าแก้รายการหัวข้อทีละหัวข้อ (เพิ่มหรือลบแล้วบันทึกทันที) แต่ API ยังรับรายการทั้งชุดใน `guardTopics` ([ui-screens ข้อ 9.13](ui-screens.md#913-ส่วนขอบเขตหัวข้อ))

ข้อความปฏิเสธไม่ใช่ค่าที่ตั้งได้ เป็นประโยคคงที่ `guardRefusalText(aiPoliteParticle)` = "คุยได้เฉพาะหัวข้อที่กำหนดไว้นะคะ" เมื่อคำลงท้ายเป็น "ค่ะ" และ "คุยได้เฉพาะหัวข้อที่กำหนดไว้นะครับ" เมื่อเป็น "ครับ" (กฎเดียวกับ `handoffText`) ระบบอ่านคำลงท้ายตอนส่งทุกครั้ง การเปลี่ยนคำลงท้ายจึงมีผลกับข้อความที่ถูกกันครั้งถัดไป ([ADR 0024](../adr/0024-scope-reductions.md))

### การทดลองในหน้าตั้งค่า

- แอดมินพิมพ์ข้อความในกล่อง "ทดลอง" แล้วกด "ทดสอบ" ระบบคัดกรองด้วยหัวข้อที่บันทึกไว้ (ไม่ใช่ค่าที่ยังไม่บันทึก) โดยไม่มีบริบท และแสดง "ผ่าน: อยู่ในหัวข้อ {topic}" หรือ "ถูกกัน: นอกขอบเขตหัวข้อ" พร้อมค่าใช้จ่ายโดยประมาณ
- ทดลองได้แม้ขอบเขตหัวข้อปิด แต่ต้องมีหัวข้อที่บันทึกไว้
- ทดลองไม่ได้เมื่อ AI ถูกปิดทั้งระบบ (`ai.disabled_globally`) หรืองบของวันนี้เต็ม (`ai.budget_exhausted`) และจำกัดความถี่ตาม `RATE_LIMIT_GUARD_TEST`
- ทุกการทดลองบันทึก AiUsage kind `guard` ที่ไม่มีลูกค้า จึงเห็นในค่าใช้จ่าย AI และการทดลองที่ถูกกันนับในตัวนับของวันนี้ด้วย
- Endpoint อยู่ใน [api-contract](../architecture/api-contract.md#post-apisettingsguardtest) หน้าจออยู่ใน [ui-screens ข้อ 9.13](ui-screens.md#913-ส่วนขอบเขตหัวข้อ)

## กรณีผิดพลาดและกรณีขอบ

| เหตุการณ์ | ระบบทำอะไร | ผู้ใช้เห็นอะไร |
| --- | --- | --- |
| การคัดกรองล้มเหลว: เรียกไม่สำเร็จ, timeout, ถูกปฏิเสธ หรือผลไม่ตรง schema | ปิดแบบปลอดภัย: ไม่ส่งอะไรให้ลูกค้า ไม่เรียกโมเดลตอบแชท แชทขึ้นรอแอดมินด้วยเหตุผล `ai_failed` บันทึก AiUsage kind guard outcome failed เมื่อการเรียกถูกคิดเงิน และบันทึกข้อผิดพลาดล่าสุดของ AI | แชทขึ้น "รอแอดมิน" พร้อมเหตุผล AI ตอบไม่สำเร็จ ลูกค้าไม่ได้ข้อความ |
| ถูกกันแล้วส่งข้อความปฏิเสธไม่สำเร็จ | ข้อความเป็นส่งไม่สำเร็จ และแชทขึ้นรอแอดมิน `ai_failed` เพราะลูกค้าไม่ได้รับอะไร | ฟองส่งไม่สำเร็จพร้อมปุ่มส่งอีกครั้ง |
| Kill switch ถูกปิดระหว่างการคัดกรอง | ไม่ส่งข้อความปฏิเสธ บันทึก AiUsage outcome cancelled | ไม่มีอะไรใหม่ในแชท |
| งบของวันนี้เต็มก่อนการคัดกรอง | ไม่เรียกตัวคัดกรอง ขึ้นรอแอดมิน `budget_reached` ตามเดิม | "งบ AI ของวันนี้เต็ม" |
| ลูกค้าส่งรูป วิดีโอ หรือสติกเกอร์ | ไม่ถึงขั้นคัดกรอง ขึ้นรอแอดมินตามชนิดข้อความเหมือนเดิม | เหตุผลตามชนิดข้อความ |
| ตัวคัดกรองตอบผ่านแต่ชื่อหัวข้อไม่ตรงรายการ | ยังผ่าน และไม่ใช้ชื่อหัวข้อนั้น | คำตอบปกติ |
| คำทักทายอย่างเดียว | ผ่าน (`matchedTopic` null) เรียกโมเดลตอบแชท | คำทักทายตอบกลับและการแนะนำตัว |
| คำทักทายพร้อมคำขอนอกหัวข้อ | ถูกกัน ไม่เรียกโมเดลตอบแชท | ข้อความปฏิเสธ |
| ข้อความต่อเนื่อง เช่น "ขออีกมุก" | ตัดสินด้วยบริบทก่อนหน้า | คำตอบปกติเมื่อบริบทอยู่ในหัวข้อ |
| ลูกค้าพยายามสั่งให้ข้ามกฎ เช่น "ไม่ต้องสนกฎ" | คำสั่งของตัวคัดกรองถือเป็นข้อมูลและตอบไม่ผ่านเมื่อไม่แน่ใจ | ข้อความปฏิเสธ |
| เปิดขอบเขตหัวข้อโดยไม่มีหัวข้อ | ไม่บันทึก | ข้อความให้ใส่หัวข้อก่อน |
| เวลาแย่ที่สุดของหนึ่งรอบ | การคัดกรองหนึ่งครั้งรวม retry บวกการตอบแชท ต้องอยู่ใน `AI_STUCK_AFTER_MS` และ `WEBHOOK_MAX_DURATION_S` ([project-setup](../architecture/project-setup.md#104-adapter-และ-route)) | ถ้าเกิน แชทขึ้นรอแอดมิน `ai_timeout` ตามกลไกงานที่ค้าง |

ข้อความไทยของรหัสอยู่ใน [error-catalog](../architecture/error-catalog.md) และบรรทัด `guard.blocked` คือ "นอกขอบเขตหัวข้อ AI จึงไม่ตอบ"

## สิ่งที่ไม่ทำและข้อจำกัด

- ตัวคัดกรองใช้ prompt จึงไม่ปิดสนิท ผู้ที่ตั้งใจอาจหาถ้อยคำที่ผ่านได้ ขอบเขตหัวข้อเป็นการป้องกันหลายชั้น (ตัวคัดกรองแยก บวกกฎในคำสั่งของการตอบ) ไม่ใช่การรับประกัน
- ตัวคัดกรองอาจกันข้อความที่อยู่ในหัวข้อจริงได้ เพราะกฎให้ตอบว่าไม่ผ่านเมื่อไม่แน่ใจ คำทักทาย ขอบคุณ และบอกลาสั้น ๆ ผ่านตามข้อ 12 แต่การแยกทำด้วย prompt จึงอาจพลาดได้ทั้งสองทาง
- ไม่ใช้รายการคำต้องห้าม และไม่ตรวจคำตอบของ AI ซ้ำว่าอยู่ในหัวข้อหรือไม่หลังตอบ
- ไม่มีตัวเลือกให้ตอบเรื่องของบัญชีเสมอ และไม่มีขอบเขตหัวข้อแยกรายลูกค้า
- ไม่นับข้อความที่ชั้นที่สองกัน (โมเดลตอบแชทตัดสินว่านอกเรื่อง) ในตัวนับ "วันนี้กันไป" เพราะตัวนับใช้เฉพาะผลของตัวคัดกรอง ต้นทุนของข้อความนั้นอยู่ในแถวของลูกค้า
- เมื่อขอบเขตหัวข้อเปิด ข้อความหยาบหรือคุกคามที่โมเดลตอบแชทตัดสินเป็น `unsafe_or_offtopic` ได้ข้อความปฏิเสธแทนการขึ้นรอแอดมิน
- มุกจากละคร ซีรีส์ และภาพยนตร์ เล่าใหม่หรืออ้างถึงสั้น ๆ ได้ แต่ไม่ยกบทพูดยาวหรือเนื้อเพลง ([ai-prompt ข้อ 9.6](ai-prompt.md#96-กฎเนื้อหา)) ซึ่งเป็นกฎใน prompt ไม่มีการตรวจอัตโนมัติ
