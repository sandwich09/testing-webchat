# หน้าตั้งค่า

> สถานะ: สร้างแล้ว · อัปเดตล่าสุด: 2026-11-19

## เป้าหมาย

แอดมินเชื่อม LINE OA, ควบคุม AI, ดูแลคลังความรู้ และเห็นค่าใช้จ่าย ได้จากหน้าเดียว

หน้าตั้งค่าแบ่งเป็นห้าแท็บ ไม่ต้องเลื่อนหน้ายาว: AI (การทำงาน, ตัวตนและน้ำเสียง), ความรู้และขอบเขต (ความรู้ที่ใช้ตอบ ซึ่งรวมขอบเขตคำตอบกับคลังความรู้, ขอบเขตหัวข้อ), LINE (การเชื่อมต่อ, Rich menu, ข้อความต้อนรับ), ค่าใช้จ่าย และสถานะระบบ แต่ละแท็บเป็นการ์ด แถวในการ์ดเดียวกันไม่มีเส้นคั่น แท็บที่เปิดอยู่ใน URL (`?tab=`) ไม่ระบุแท็บเปิดแท็บ AI ยกเว้นยังไม่ได้เชื่อม LINE ซึ่งเปิดแท็บ LINE ทุก dropdown ใช้ตัวเลือกในธีมของแอป ([ui-screens ข้อ 1.8](ui-screens.md#18-select) และ [ข้อ 9.2](ui-screens.md#92-โครงร่วม), [ADR 0031](../adr/0031-settings-tabs-user-wording-and-neutral-prompt.md))

## ส่วน AI ตอบแทน

| รายการ | พฤติกรรม |
| --- | --- |
| เปิดใช้ AI ทั้งระบบ | Kill switch ปิดแล้ว AI หยุดตอบผู้ใช้ทุกคนทันที มีผลกับข้อความที่กำลังประมวลผลด้วย |
| โมเดล | เลือกจาก Claude Opus 5.5, Claude Sonnet 5.5 (ค่าเริ่มต้นของระบบที่ติดตั้งใหม่), Claude Haiku 5.5 มีผลกับข้อความถัดไป ระบบที่ติดตั้งก่อน [ADR 0026](../adr/0026-neutral-core-prompt-and-layered-settings.md) คงโมเดลที่บันทึกไว้ แอดมินเปลี่ยนเองที่นี่ |
| งบต่อวัน | เป็นดอลลาร์ ถึงเพดานแล้ว AI หยุดจนถึงเที่ยงคืนตามเวลาไทย และแสดงยอดที่ใช้ไปวันนี้ |
| คำลงท้าย | "ค่ะ" (ค่าเริ่มต้น) หรือ "ครับ" |
| ชื่อ AI | ข้อความบรรทัดเดียว ไม่เกิน `AI_NAME_MAX_CHARS` ตัวหลังตัดช่องว่าง เว้นว่างได้ (ค่าเริ่มต้นว่าง) AI ใช้ชื่อนี้ตามที่พิมพ์เมื่อเรียกตัวเองและเมื่อแนะนำตัว ไม่เติมคำนำหน้า ว่างแล้ว AI เรียกตัวเองว่า "ผู้ช่วย AI" บันทึกด้วยปุ่ม "บันทึก" ที่ขึ้นเมื่อค่าเปลี่ยน หรือ Enter |
| ขอบเขตคำตอบ | "คุยทั่วไปได้" (`general` ค่าเริ่มต้น) หรือ "ตอบจากคลังความรู้เท่านั้น" (`knowledge_only`) เลือกแล้วบันทึกทันที ([ai-prompt ข้อ 2.2.1](ai-prompt.md#221-บรรทัดของขอบเขตคำตอบ)) |
| คำแนะนำสำหรับ AI | ข้อความที่แอดมินเขียนเอง กำหนดบทบาท น้ำเสียง เรื่องที่คุยได้ คำทักทาย และข้อห้ามเพิ่มได้ แต่ลบล้างกฎของระบบไม่ได้ ค่าเริ่มต้นว่าง |

รายละเอียดของ AI อยู่ใน [ai-reply](ai-reply.md)

## ส่วนขอบเขตหัวข้อ

| รายการ | พฤติกรรม |
| --- | --- |
| จำกัดหัวข้อที่ AI คุยได้ | สวิตช์เปิดปิดขอบเขตหัวข้อ เปิดได้เมื่อมีหัวข้ออย่างน้อยหนึ่งหัวข้อ |
| หัวข้อที่คุยได้ | รายการหัวข้อ เพิ่มทีละหัวข้อจากช่องข้อความ (ปุ่ม "เพิ่ม" หรือ Enter) และลบได้ทีละหัวข้อ บันทึกทันทีเมื่อเพิ่มหรือลบ ไม่เกิน `GUARD_MAX_TOPICS` หัวข้อ ห้ามซ้ำ พร้อมตัวนับ หัวข้อสุดท้ายลบไม่ได้ขณะขอบเขตหัวข้อเปิด |
| ทดลอง | พิมพ์ข้อความแล้วกด "ทดสอบ" เห็นผลว่าผ่านหรือถูกกันพร้อมค่าใช้จ่ายโดยประมาณ กดไม่ได้เมื่อ AI ถูกปิดทั้งระบบ |
| วันนี้กันไปกี่ข้อความ | ตัวนับของวันนี้ตามเวลาไทย |

ทุก control แก้ได้แม้ kill switch ปิด ข้อความที่ผู้ใช้ได้เมื่อถูกกันเป็นประโยคคงที่ คำลงท้ายตามคำลงท้ายของส่วน AI ตอบแทน ไม่ตั้งค่าในหน้านี้ รายละเอียดอยู่ใน [topic-guard](topic-guard.md)

## ส่วน LINE Official Account

1. แสดงชื่อและ Basic ID ของ OA ที่เชื่อมอยู่ พร้อมสถานะ เวลาที่รับข้อความล่าสุด และสิ่งที่รู้เกี่ยวกับ Channel secret: LINE ยืนยันแล้ว, ยังตรวจกับ LINE ไม่ได้ (ให้กด "ทดสอบการเชื่อมต่อ" ภายหลัง) หรือยังไม่ได้ตรวจเพราะยังไม่มี Channel ID
2. แสดง Webhook URL แบบอ่านอย่างเดียว พร้อมปุ่ม "คัดลอก"
3. กรอก Channel ID, Channel secret และ Channel access token ได้ Channel ID เป็นตัวเลขเท่านั้นไม่เกิน `LINE_CHANNEL_ID_MAX_CHARS` หลัก ไม่ใช่ความลับ จึงแสดงค่าที่บันทึกไว้ ส่วน Channel secret และ Channel access token ระบบไม่แสดงค่าเดิมกลับ ไม่ว่าในรูปแบบใด ช่องที่มีค่าบันทึกแล้วล็อกไว้ (Channel ID แสดงค่าที่บันทึก สองค่าลับแสดงเครื่องหมายคงที่ที่ไม่บอกค่าหรือความยาว) และเปิดแก้ทีละช่องด้วยปุ่มดินสอ ซึ่งล้างช่องให้พิมพ์ค่าใหม่ ปุ่ม X ยกเลิกการแก้ช่องนั้น ระบบส่งเฉพาะช่องที่แก้ ค่าอื่นใช้ค่าที่บันทึกไว้ และการตรวจในข้อ 4 ใช้ทั้งสามค่าเสมอ ก่อนเชื่อม LINE ทั้งสามช่องเปิดให้กรอกเลย ([ui-screens ข้อ 9.4](ui-screens.md#94-ส่วน-line-official-account), [ADR 0031](../adr/0031-settings-tabs-user-wording-and-neutral-prompt.md))
4. เมื่อบันทึก ระบบตรวจกับ LINE ก่อนสามเรื่อง: access token ใช้ได้, Channel secret เป็นของ Channel ID นั้น (LINE ออก token อายุสั้นแบบ client credentials ให้เมื่อคู่ถูก ระบบเพิกถอนทันที ไม่เก็บและไม่ log) และ access token เป็นของ channel เดียวกัน (ก่อนเพิกถอน token อายุสั้นอ่านบอทของ channel แล้วเทียบกับบอทของ access token ถ้าต่างกัน webhook ทุกครั้งจะตรวจ signature ไม่ผ่าน) ถ้าข้อใดไม่ผ่าน ไม่บันทึกและบอกเหตุผล ถ้าอ่านบอทของ channel ไม่ได้ สถานะเป็นยังตรวจ Channel secret ไม่ได้ ถ้า LINE ตอบการตรวจ secret ไม่ได้ (429, 5xx, ไม่มีเครือข่าย, timeout) ระบบบันทึกให้ และสถานะแสดงว่ายังตรวจ Channel secret ไม่ได้
5. ปุ่ม "ทดสอบการเชื่อมต่อ" เรียก LINE เพื่อยืนยันว่า access token ยังใช้ได้ และตรวจ Channel secret กับ Channel ID ที่บันทึกไว้ด้วย ผลบอกทั้งสองเรื่อง
6. Credential ที่บันทึกไว้ก่อนมีช่อง Channel ID ยังใช้รับและส่งข้อความได้ตามเดิม สถานะบอกว่ายังไม่ได้ตรวจ Channel secret จนกว่าจะบันทึกใหม่พร้อม Channel ID

ขั้นตอนฝั่ง LINE อยู่ใน [runbooks/line-oa-setup](../runbooks/line-oa-setup.md)

## ส่วน Rich menu และข้อความต้อนรับ

พฤติกรรมของปุ่มและการ์ดอยู่ใน [line-messaging](line-messaging.md#rich-menu) เหตุผลอยู่ใน [ADR 0027](../adr/0027-rich-menu-and-welcome-card.md)

1. แถวสถานะ: "Publish แล้ว" พร้อมเวลา หรือ "ยังไม่ได้ publish" ปุ่ม "Publish rich menu" ("Publish อีกครั้ง" เมื่อ publish แล้ว) และ "นำ rich menu ออก" (เมื่อ publish แล้ว) ถ้ายังไม่เชื่อม LINE ปุ่มปิดและคำอธิบายบอกให้เชื่อมก่อน ความล้มเหลวล่าสุดแสดงใต้ปุ่มเป็น "ครั้งล่าสุดไม่สำเร็จ: …" จนกว่าจะทำสำเร็จ และ toast บอกผลทุกครั้ง
2. "ข้อความวิธีทดสอบ": ช่องหลายบรรทัด ตัวนับ `{n}/{max}` ไม่เกิน `HOW_TO_TEXT_MAX_CHARS` ปุ่ม "บันทึก" เมื่อแก้ และ "ใช้ข้อความเริ่มต้น" เมื่อมีข้อความที่บันทึกเอง บันทึกไม่สำเร็จแล้วข้อความที่พิมพ์ยังอยู่ ค่าที่ตรงกับข้อความเริ่มต้นถูกบันทึกเป็นค่าว่าง ข้อความจึงยังลงท้ายตามคำลงท้ายที่ตั้ง
3. สวิตช์ "ส่งข้อความต้อนรับเมื่อเพิ่มเพื่อน" ค่าเริ่มต้นเปิด
4. "ข้อความต้อนรับ": เหมือนข้อ 2 ไม่เกิน `WELCOME_TEXT_MAX_CHARS`
5. ตัวอย่างการ์ดต้อนรับแบบอ่านอย่างเดียว: หัว gradient, "ยินดีต้อนรับสู่" กับชื่อ LINE OA (หรือ "Test webchat"), ข้อความต้อนรับที่บันทึก บรรทัดหมายเหตุ และสามปุ่มที่กดไม่ได้

## ส่วนสถานะระบบ

แสดงเพื่อให้รู้ว่าระบบทำงานอยู่ โดยไม่ต้องเปิด log

- เวลาที่รับ webhook ล่าสุด
- ข้อผิดพลาดล่าสุดของ LINE และของ AI พร้อมเวลา
- งบ AI ที่ใช้ไปวันนี้เทียบกับเพดาน
- สถานะการต่อฐานข้อมูล

## กรณีผิดพลาด

| เหตุการณ์ | แอดมินเห็นอะไร |
| --- | --- |
| Token ของ LINE ไม่ถูกต้อง | "Channel access token ไม่ถูกต้อง ตรวจค่าที่คัดลอกมาอีกครั้ง" และค่าที่กรอกยังอยู่ |
| Channel ID กับ Channel secret ไม่ใช่คู่กัน | "Channel ID กับ Channel secret ไม่ตรงกัน ตรวจว่าคัดลอกทั้งสองค่ามาจาก channel เดียวกัน" ไม่บันทึก และค่าที่กรอกยังอยู่ |
| Channel access token เป็นของ channel อื่น (`line.channel_mismatch`) | "Channel access token เป็นของ channel อื่น ไม่ใช่ channel ของ Channel ID นี้ คัดลอกทั้งสามค่าจาก channel เดียวกันใน LINE Developers Console" ไม่บันทึก และค่าที่กรอกยังอยู่ "ทดสอบการเชื่อมต่อ" บอกข้อเดียวกันเมื่อค่าที่บันทึกไว้เป็นแบบนี้ |
| LINE ตรวจ Channel secret ไม่ได้ตอนบันทึก | บันทึกแล้ว และสถานะแสดง "ยังตรวจ Channel secret กับ LINE ไม่ได้ กด "ทดสอบการเชื่อมต่อ" อีกครั้งภายหลัง" |
| Channel ID ไม่ใช่ตัวเลข หรือยาวเกิน | "Channel ID เป็นตัวเลขเท่านั้น ไม่เกิน {max} หลัก" ใต้ช่อง ไม่ส่งถึง server |
| บันทึกไม่สำเร็จเพราะระบบ | "บันทึกไม่สำเร็จ ข้อมูลที่กรอกยังอยู่ ลองอีกครั้ง" |
| ยังไม่ได้ตั้งค่า LINE OA | ส่วน LINE แสดงขั้นตอนเริ่มต้น และหน้าแชทแจ้งให้มาตั้งค่า |
| Publish หรือนำ rich menu ออกไม่สำเร็จ | toast ด้วยข้อความของรหัส และ "ครั้งล่าสุดไม่สำเร็จ: …" ใต้ปุ่ม เมนูเดิมยังอยู่ตามเดิม |

## สิ่งที่ไม่ทำ

- กรอก API key ของ AI ผ่านหน้าเว็บ (อยู่ใน environment variable)
- เปลี่ยนรหัสเข้าใช้ผ่านหน้าเว็บ
- หลาย LINE OA

## วิธีทดสอบ

- Unit: การตรวจค่าที่กรอก (รวมรูปแบบของ Channel ID), การเข้ารหัส credential, การไม่คืนค่าความลับใน response, ผลของการตรวจ Channel secret ทั้งสามแบบ
- Adapter: การตรวจ Channel secret แบบ client credentials กับ stub การอ่านบอทของ channel ด้วย token นั้น และการเพิกถอน token (stub ตอบบอทอื่นสำหรับ `STUB_OTHER_CHANNEL_ACCESS_TOKEN`)
- E2E เส้นที่ 4, 6, 9, 14 และ 15
