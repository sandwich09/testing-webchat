# หน้าแชท

> สถานะ: สร้างแล้ว · อัปเดตล่าสุด: 2026-11-19

## เป้าหมาย

แอดมินเห็นว่าใครทักมา เลือกลูกค้า อ่านประวัติ และตอบกลับได้เร็ว โดยรู้เสมอว่าข้อความของตัวเองส่งถึงหรือไม่

โครงหน้าและ design system อยู่ใน [frontend](../architecture/frontend.md)

## รายชื่อลูกค้า

1. แต่ละแถวแสดง: รูปโปรไฟล์ (หรือตัวอักษรแรกของชื่อ), ชื่อ, ข้อความล่าสุดหนึ่งบรรทัด (ของใครก็ได้), เวลาของข้อความล่าสุดของลูกค้า และจำนวนยังไม่อ่าน
2. ข้อความล่าสุดบอกผู้ส่งฝั่งแอดมินด้วยคำนำ "คุณ:" หรือ "AI:" และสื่อแสดงเป็นคำ เช่น "รูปภาพ", "วิดีโอ", "สติกเกอร์"
3. แถวที่ยังไม่อ่านใช้ชื่อตัวหนา
4. แชทที่รอแอดมินแสดงคำว่า "รอแอดมิน" นำหน้าข้อความล่าสุด
5. ลูกค้าที่เลิกติดตามแสดงเป็นสีจางพร้อมคำว่า "เลิกติดตามแล้ว"
6. เรียงตามเวลาข้อความล่าสุดที่ลูกค้าส่งเข้ามา ใหม่ไปเก่า ลูกค้าที่ยังไม่เคยส่งข้อความใช้เวลาที่เพิ่มเพื่อน (เวลาที่สร้างแถว) ข้อความของแอดมินหรือ AI, การ์ดต้อนรับ, บรรทัดเหตุการณ์, การอ่าน และการเปลี่ยนสวิตช์ไม่ย้ายแถว (การกดปุ่มของลูกค้านับเป็นข้อความของลูกค้า) ข้อความใหม่ของลูกค้าย้ายแถวขึ้นบนสุดในรอบ polling ถัดไปโดยไม่ต้องโหลดหน้าใหม่ เวลาในแถวจึงเป็นค่าเดียวกับที่ใช้เรียง ส่วนข้อความล่าสุดอาจเป็นของฝั่งแอดมินที่ตอบทีหลัง รายการโหลดทีละ `CONTACT_PAGE_LIMIT` คน และโหลดหน้าถัดไปเมื่อเลื่อนถึงท้ายรายการ (ไม่มีเลขหน้า) รายการเลื่อนในคอลัมน์ของตัวเอง หน้าไม่เลื่อนทั้งหน้า
7. ตัวกรอง: ทั้งหมด, ยังไม่อ่าน, รอแอดมิน พร้อมจำนวน
8. ค้นหาจากชื่อลูกค้า
9. รูปแบบเวลา: วันนี้แสดงเวลา, เมื่อวานแสดง "เมื่อวาน", ภายในสัปดาห์แสดงชื่อวันย่อ, เก่ากว่านั้นแสดงวันที่

## ห้องแชท

1. ส่วนหัว: รูป, ชื่อ, สถานะการติดตาม, สวิตช์ "AI ตอบแทน" และปุ่มเปิดปิดแผงข้อมูลลูกค้า
2. ข้อความของลูกค้าอยู่ซ้าย ของฝั่งแอดมินอยู่ขวา ข้อความที่ส่งติดกันจัดเป็นกลุ่ม
3. ข้อความฝั่งแอดมินระบุผู้ส่งว่า "คุณ" หรือ "AI" ข้างเวลา
4. ตัวคั่นวันที่ และบรรทัดแจ้งเหตุการณ์ เช่น "ลูกค้าส่งรูป AI จึงหยุดรอแอดมิน" บรรทัดเหตุการณ์เป็นข้อความที่บันทึกไว้ จึงอยู่ตามลำดับเวลาที่เกิด ข้อความไทยอยู่ใน [error-catalog](../architecture/error-catalog.md#บรรทัดเหตุการณ์) การกดปุ่มของ rich menu หรือการ์ดต้อนรับแสดงเป็นบรรทัด "ลูกค้ากดปุ่ม …" และการ์ดต้อนรับที่ส่งเมื่อเพิ่มเพื่อนแสดงเป็นกล่อง "ข้อความต้อนรับ" ที่มีชื่อปุ่มแบบกดไม่ได้ ([line-messaging](line-messaging.md#rich-menu))
5. ข้อความแสดงเป็นข้อความล้วนเสมอ ลิงก์เปิดแท็บใหม่ และข้อความยาวหรือ URL ไม่ล้นฟอง
6. รูปและวิดีโอแสดงภาพตัวอย่าง กดเพื่อดูขนาดเต็ม ข้อความเสียงแสดงตัวเล่นเล็กในฟอง (ปุ่มเล่นหรือหยุด แถบตำแหน่งที่เลื่อนได้ และเวลาที่เล่นไปกับความยาว) ไม่เล่นเอง และเล่นได้ทีละข้อความ ระหว่างดาวน์โหลด ล้มเหลว หรือใหญ่เกินแสดงสถานะแบบเดียวกับรูป รายชื่อแสดง "ข้อความเสียง" ข้อความที่ลูกค้าตอบกลับ ("ตอบกลับ" ของ LINE) มีกล่องอ้างอิงเล็กเหนือข้อความ: ป้ายผู้เขียน ("คุณ", "AI" หรือชื่อลูกค้า) และข้อความหนึ่งบรรทัดที่ตัดแล้ว หรือป้ายชนิดสื่อ กดแล้วเลื่อนไปที่ข้อความต้นทางและเน้นสั้น ๆ เมื่อข้อความนั้นโหลดอยู่ ไม่อยู่ก็ไม่ทำอะไร ข้อความต้นทางที่ระบบไม่รู้จักแสดง "ข้อความต้นทางไม่พร้อมแสดง" สีจาง ([line-messaging](line-messaging.md#ข้อความที่ตอบกลับ)) แอดมินอ้างถึงข้อความของลูกค้าตอนตอบไม่ได้ (งานที่อาจทำต่อ)
7. เปิดแชทแล้วจำนวนยังไม่อ่านถูกล้าง
8. โหลด `MESSAGE_PAGE_LIMIT` ข้อความล่าสุด และโหลดเพิ่มเมื่อเลื่อนขึ้น
9. เลื่อนตามข้อความใหม่เฉพาะเมื่ออยู่ล่างสุด ถ้าเลื่อนขึ้นไปแล้วมีข้อความใหม่ แสดงปุ่ม "ข้อความใหม่"

## ช่องตอบ

1. ช่องพิมพ์ข้อความ, ปุ่มแนบรูปหรือวิดีโอ และปุ่ม "ส่ง"
2. Enter ส่ง และ Shift+Enter ขึ้นบรรทัดใหม่
3. ข้อความขึ้นในห้องแชททันทีในสถานะ "กำลังส่ง"
4. กดส่งซ้ำหรือ retry กี่ครั้ง ลูกค้าได้รับข้อความเดียว
5. การแนบไฟล์แสดงความคืบหน้าและยกเลิกได้ ข้อกำหนดของไฟล์อยู่ใน [line-messaging](line-messaging.md)
6. ช่องตอบถูกปิดเมื่อลูกค้าเลิกติดตาม หรือยังไม่ได้ตั้งค่า LINE OA พร้อมบอกเหตุผล
7. เมื่อแอดมินส่งข้อความ AI ตอบแทนของลูกค้าคนนั้นถูกปิด สถานะรอแอดมินถูกล้าง และมีบรรทัดเหตุการณ์ AI กลับมาเมื่อเปิดสวิตช์อีกครั้งเท่านั้น ดู [ai-reply](ai-reply.md#เมื่อแอดมินตอบเอง)
8. เมื่อแอดมินเริ่มพิมพ์ ระบบขอให้ LINE แสดง loading ในแอปของลูกค้าเป็นเวลา `LINE_LOADING_SECONDS` หน้าเว็บส่งไม่เกินหนึ่งครั้งต่อ `TYPING_PING_INTERVAL_MS` ขณะพิมพ์ และ server จำกัดไม่เกิน `RATE_LIMIT_TYPING` ต่อลูกค้า ถ้าเรียกไม่สำเร็จไม่ถือเป็นความล้มเหลว

## แผงข้อมูลลูกค้า

- รูป ชื่อ และวันที่เพิ่มเพื่อน
- สวิตช์ "AI ตอบแทน" พร้อมคำอธิบายหนึ่งบรรทัด
- รายละเอียด: สถานะ, จำนวนข้อความทั้งหมด, จำนวนครั้งที่ AI ตอบ และเวลาที่ทักล่าสุด
- ไม่แสดง token หรือค่าใช้จ่าย ซึ่งอยู่ในหน้าตั้งค่าเท่านั้น

## โน้ตของแอดมิน

แอดมินเขียนโน้ตเกี่ยวกับลูกค้าไว้ในแผงข้อมูลลูกค้า ส่วน "โน้ต (เห็นเฉพาะแอดมิน)" ได้หลายโน้ตต่อลูกค้า

1. โน้ตเป็นข้อมูลของแอดมินเท่านั้น: ไม่ถูกส่งไป LINE ไม่อยู่ในสิ่งใดที่ส่งให้โมเดล AI (ประวัติ คำสั่ง การคัดกรอง) และไม่อยู่ใน log (log มีแค่ `contactId`)
2. หนึ่งโน้ตมีข้อความ (ตัดช่องว่างหัวท้ายแล้ว 1 ถึง `CONTACT_NOTE_MAX_CHARS` ตัว ขึ้นบรรทัดได้) และเวลาที่เขียน เพิ่มและลบได้ แก้ไม่ได้
3. รายการเรียงใหม่ไปเก่า แสดงไม่เกิน `CONTACT_NOTE_LIST_LIMIT` โน้ต เวลาแสดงตามกฎ "วันและเวลาของเหตุการณ์" ใน [ux-writing](../guidelines/ux-writing.md#วันที่และเวลา)
4. Enter เพิ่มโน้ต Shift+Enter ขึ้นบรรทัดใหม่ โน้ตขึ้นบนสุดทันที (optimistic) ถ้าบันทึกไม่สำเร็จ โน้ตหายไปจากรายการ ข้อความที่พิมพ์กลับมาในช่อง และมีข้อความผิดพลาดใต้ช่อง
5. ลบต้องยืนยันใน dialog เหมือนการลบไฟล์ในคลังความรู้
6. การเพิ่มจำกัดความถี่ตาม `RATE_LIMIT_NOTE_CREATE` ต่อ IP
7. รายการโหลดเมื่อเปิดแผงและหลังเพิ่มหรือลบ ไม่ polling (แอดมินหลายคนเห็นโน้ตของกันเมื่อเปิดแผงใหม่)
8. ลบลูกค้าไม่มีในระบบ ถ้ามีในอนาคต โน้ตถูกลบตาม (foreign key แบบ cascade)

## สวิตช์ AI ตอบแทนเมื่อ kill switch ปิด

เมื่อ "เปิดใช้ AI ทั้งระบบ" ในหน้าตั้งค่าถูกปิด สวิตช์รายลูกค้าทั้งในส่วนหัวและแผงข้อมูลกดไม่ได้ แสดงเป็นปิด และมีข้อความ "AI ถูกปิดทั้งระบบ เปิดได้ที่ ตั้งค่า › AI ตอบแทน" ค่าเดิมของแต่ละลูกค้ายังถูกจำไว้ และกลับมาเมื่อเปิด kill switch

## กรณีผิดพลาดและกรณีขอบ

| เหตุการณ์ | แอดมินเห็นอะไร |
| --- | --- |
| ยังไม่มีลูกค้าทักมา | หน้าว่างพร้อมคำแนะนำให้ตั้งค่า LINE OA และเพิ่มเพื่อน |
| ส่งไม่สำเร็จ | ข้อความขึ้น "ส่งไม่สำเร็จ" บอกเหตุผล และมีปุ่ม "ส่งอีกครั้ง" |
| ส่งไม่สำเร็จ และผ่าน `LINE_RETRY_KEY_WINDOW_MS` นับจาก push ครั้งแรกแล้ว | ข้อความบอกว่าส่งอีกครั้งไม่ได้แล้วและให้พิมพ์ส่งใหม่ ไม่มีปุ่ม "ส่งอีกครั้ง" เพราะ LINE ลืม retry key แล้ว การส่งซ้ำอาจถึงลูกค้าสองครั้ง ([line-messaging](line-messaging.md#ส่งข้อความ) ข้อ 5) |
| รูปโปรไฟล์โหลดไม่ได้ | ตัวอักษรแรกของชื่อ |
| สื่อขาเข้าดาวน์โหลดไม่ได้ | ป้าย "โหลดรูปไม่สำเร็จ" |
| การเชื่อมต่อกับ server มีปัญหา | แถบแจ้งด้านบน และข้อความที่พิมพ์ค้างไว้ยังอยู่ |
| ส่วนหนึ่งของหน้าพัง | เฉพาะส่วนนั้นแสดงข้อผิดพลาด ส่วนอื่นยังใช้ได้ |

## สิ่งที่ไม่ทำ

แท็ก โน้ต การมอบหมายแชท และการค้นหาในเนื้อหาข้อความ

## วิธีทดสอบ

- Unit: การรวมข้อความจาก polling, การตัดรายการซ้ำ, การจัดกลุ่มข้อความ, รูปแบบเวลา
- E2E เส้นที่ 1, 2, 5 และ 7 ที่ความกว้าง 1280 และ 390 (เส้นที่ 2 ตรวจลำดับของรายชื่อด้วย) และเส้นที่ 4 ตรวจว่าหน้าไม่เลื่อนทั้งหน้า
