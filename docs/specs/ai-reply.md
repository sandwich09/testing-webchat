# AI ตอบแทน

> สถานะ: สร้างแล้ว · อัปเดตล่าสุด: 2026-11-19

## เป้าหมาย

เมื่อเปิดใช้ AI ตอบแชทแทนแอดมิน โดยเข้าใจบริบทจากประวัติแชท ตอบจากคลังความรู้ และส่งต่อให้คนเมื่อไม่รู้ ไม่เดา

## สวิตช์สองระดับ

| สวิตช์ | อยู่ที่ | ผล |
| --- | --- | --- |
| เปิดใช้ AI ทั้งระบบ (kill switch) | หน้าตั้งค่า | ปิดแล้ว AI ไม่ตอบใครเลย และสวิตช์รายผู้ใช้กดไม่ได้ |
| AI ตอบแทน | หน้าแชท รายผู้ใช้ | เปิดแล้ว AI ตอบผู้ใช้คนนั้น |

- ผู้ใช้ใหม่เริ่มต้นด้วย AI ตอบแทนปิด แอดมินเปิดเองทีละคน หรือผู้ใช้เปิดเองด้วยปุ่ม "คุยกับ AI" ของ rich menu หรือการ์ดต้อนรับ ซึ่งเปิดได้เฉพาะเมื่อ kill switch เปิดและงบยังไม่เต็ม (สองกรณีนั้นได้ข้อความคงที่และแชทรอแอดมิน) และปุ่ม "คุยกับแอดมิน" ปิด AI ของผู้ใช้คนนั้น ([line-messaging](line-messaging.md#เมื่อผู้ใช้กดปุ่ม))
- ระบบที่ติดตั้งใหม่มี kill switch ปิด ค่าเริ่มต้นทั้งหมดอยู่ใน [project-setup](../architecture/project-setup.md#101-แกนกลาง)
- ค่ารายผู้ใช้ถูกจำไว้เมื่อ kill switch ปิด
- Kill switch ถูกตรวจสองจุด: ก่อนเรียกโมเดล และก่อนส่งข้อความออก LINE

เหตุผลอยู่ใน [ADR 0011](../adr/0011-two-level-ai-switch-and-daily-budget.md)

## เงื่อนไขที่ AI จะตอบ

AI ตอบเมื่อครบทุกข้อ:

1. Kill switch เปิด
2. AI ตอบแทนของผู้ใช้เปิด
3. งบของวันนี้ยังไม่ถึงเพดาน
4. ข้อความล่าสุดเป็นข้อความตัวอักษร
5. ผู้ใช้ยังติดตามอยู่

ถ้าเงื่อนไขข้อ 3 หรือ 4 ไม่ผ่านขณะที่ข้อ 1 และ 2 ผ่าน แชทขึ้นสถานะรอแอดมินพร้อมเหตุผล

## ลำดับการตรวจ

kill switch → AI ตอบแทนของผู้ใช้ → การติดตาม → ชนิดข้อความ → งบต่อวัน → รวมข้อความรัวและล็อก → ขอบเขตหัวข้อ (เฉพาะเมื่อเปิด) → คลังความรู้และโมเดลตอบแชท

ขอบเขตหัวข้ออยู่เหนือคำแนะนำสำหรับ AI และคลังความรู้ ข้อความนอกหัวข้อได้ข้อความปฏิเสธแทนคำตอบ และไม่ขึ้นรอแอดมิน รายละเอียดอยู่ใน [topic-guard](topic-guard.md) ขั้นตอนอยู่ใน [use-cases](../architecture/use-cases.md#generateaireply)

## เมื่อแอดมินตอบเอง

เมื่อแอดมินส่งข้อความถึงผู้ใช้คนหนึ่ง:

1. AI ตอบแทนของผู้ใช้คนนั้นถูกปิด (`aiEnabled` เป็น false)
2. สถานะรอแอดมินของแชทนั้นถูกล้าง
3. แชทมีบรรทัดเหตุการณ์ว่า AI ตอบแทนถูกปิดเพราะคุณตอบเอง

ไม่มีการหยุดแบบมีเวลา AI กลับมาตอบเมื่อแอดมินเปิดสวิตช์ "AI ตอบแทน" ของผู้ใช้คนนั้นอีกครั้ง หรือเมื่อผู้ใช้กด "คุยกับ AI" และการเปิดสวิตช์ล้างสถานะรอแอดมินด้วย ขั้นตอนอยู่ใน [use-cases](../architecture/use-cases.md#sendadminmessage) และ [SetContactAi](../architecture/use-cases.md#setcontactai)

## การรวมข้อความรัว

ผู้ใช้มักพิมพ์หลายข้อความติดกัน ระบบรอช่วงสั้น ๆ (`AI_DEBOUNCE_MS` ตั้งค่าได้) แล้วตรวจว่าข้อความของรอบนี้ยังเป็นข้อความล่าสุดหรือไม่ ถ้าไม่ รอบนี้ถอนตัว รอบของข้อความล่าสุดตอบครั้งเดียว และมีการล็อกต่อ Contact ในฐานข้อมูลเพื่อไม่ให้สองรอบตอบพร้อมกัน

## สิ่งที่ส่งให้โมเดล

1. คำสั่งของระบบ: แกนที่เป็นกลาง (ตัวตน, การทักทาย, กฎการตอบ, ขอบเขตคำตอบ, คำลงท้าย) ชื่อ AI และคำแนะนำสำหรับ AI ที่แอดมินเขียน ไม่มีชื่อ LINE OA
2. คลังความรู้ทั้งหมด ผ่าน port `KnowledgeSource` ดู [knowledge-base](knowledge-base.md)
3. ข้อความล่าสุดของแชทนั้นไม่เกิน `AI_HISTORY_LIMIT` ข้อความ
4. เวลาปัจจุบันตามเวลาไทย เป็นข้อความระบบท้ายบทสนทนา เพื่อให้ตอบเรื่องที่ขึ้นกับเวลาได้ เช่น เปิดทำการอยู่หรือไม่ ถ้าคลังความรู้มีเวลาทำการ

ข้อความทั้งหมดของ prompt และโครงของ request อยู่ใน [ai-prompt](ai-prompt.md)

ข้อความของผู้ใช้และเนื้อหาจาก PDF ถูกแยกจากคำสั่งของระบบอย่างชัดเจน เพราะเป็นข้อมูลที่ไว้ใจไม่ได้ โมเดลไม่มีเครื่องมือใดให้เรียก และเห็นเฉพาะประวัติของแชทนั้น

## กฎการตอบ

- ตอบสั้นแบบแชท เป็นข้อความล้วน ไม่มี markdown
- ใช้คำลงท้ายตามที่ตั้งไว้
- บทบาทและเรื่องที่คุยมาจากคำแนะนำสำหรับ AI ถ้าว่างเป็นผู้ช่วยที่สุภาพและเป็นกันเอง
- ขอบเขตคำตอบ `general` (ค่าเริ่มต้น): ยึดคลังความรู้ก่อน เรื่องอื่นตอบจากความรู้ทั่วไปได้ แต่ข้อมูลเฉพาะของบัญชีที่ไม่มีในคลังให้แอดมินตอบ `knowledge_only`: ข้อเท็จจริงตอบจากคลังความรู้เท่านั้น ไม่มีให้แอดมินตอบ
- ผู้ใช้ทักทายและยังไม่เคยแนะนำตัวในประวัติ: ทักกลับ แนะนำตัวสั้น ๆ (บอกชื่อ AI เมื่อตั้งไว้) แล้วถามว่ามีอะไรให้ช่วย
- ไม่เดา ไม่อ้างว่าเป็นคน ถ้าถูกถามให้ตอบว่าเป็นผู้ช่วย AI
- คำสั่งของระบบไม่มีความลับใด ๆ
- ส่งลิงก์ได้เฉพาะลิงก์ที่อยู่ในคลังความรู้หรือคำแนะนำสำหรับ AI ระบบตรวจซ้ำหลังโมเดลตอบ ([ai-prompt ข้อ 6.1](ai-prompt.md#61-ลิงก์ในคำตอบ))

## รูปแบบคำตอบ

โมเดลคืนคำตอบแบบมีโครงสร้าง: ข้อความตอบ, ธงว่าต้องการแอดมินหรือไม่ และเหตุผลเมื่อต้องการแอดมิน ระบบตรวจซ้ำด้วย schema ตาม [ai-prompt](ai-prompt.md#5-รูปแบบคำตอบ)

| ผล | ระบบทำอะไร |
| --- | --- |
| ตอบได้ | ส่งข้อความให้ผู้ใช้ |
| ต้องการแอดมิน | ส่งข้อความแจ้งคงที่ "ขออนุญาตให้แอดมินมาตอบเรื่องนี้นะคะ" (คำลงท้าย "ค่ะ") หรือ "ขออนุญาตให้แอดมินมาตอบเรื่องนี้นะครับ" (คำลงท้าย "ครับ") แทนข้อความของโมเดล และแชทขึ้นสถานะรอแอดมินด้วยเหตุผลที่โมเดลเลือก |
| ไม่ตรง schema, โมเดลปฏิเสธ, มีลิงก์ที่แอดมินไม่ได้เขียน (`ai.link_not_allowed`) หรือเรียกไม่สำเร็จ | ไม่ส่งอะไรให้ผู้ใช้ และแชทขึ้นสถานะรอแอดมินพร้อมเหตุผล การเรียกที่ส่งไปแล้วไม่ได้คำตอบ (`ai.no_response`) มีแถวค่าใช้จ่ายที่ยอดเป็นศูนย์ ([usage-cost](usage-cost.md#การเรียกที่ไม่ได้คำตอบ)) |

## การส่ง

ระหว่างรอ ระบบแสดง loading ฝั่ง LINE แล้วส่งด้วย reply token ถ้ายังใช้ได้ ไม่เช่นนั้น push ดู [line-messaging](line-messaging.md) ข้อความของ AI มีผู้ส่งเป็น "AI" ในหน้าแชท

## โมเดลและผู้ให้บริการ

- เรียกผ่าน port `ChatModel` ด้วย SDK ทางการของ Anthropic ใน adapter
- ค่าเริ่มต้นของระบบที่ติดตั้งใหม่ `claude-sonnet-5-5` (`DEFAULT_AI_MODEL`) เลือก `claude-opus-5-5` หรือ `claude-haiku-5-5` ได้ในหน้าตั้งค่า แถว Settings ที่มีอยู่แล้วคงค่าเดิม ([ADR 0026](../adr/0026-neutral-core-prompt-and-layered-settings.md)) การตอบแชทของ Sonnet 5.5 ไม่ใช้การสลับโมเดลสำรองฝั่ง server เมื่อโมเดลปฏิเสธ แชทจึงขึ้นรอแอดมินทันที
- ระดับการคิด (effort) `low`
- การตอบแชทไม่ stream เพราะ LINE แสดงข้อความทีละก้อน ใช้ `AI_MAX_TOKENS`, timeout `CLAUDE_REPLY_TIMEOUT_MS` และ retry ของ SDK `CLAUDE_REPLY_MAX_RETRIES` และทั้งการเรียกถูกตัดที่ `callDeadlineMs` ([project-setup](../architecture/project-setup.md#10-ค่าคงที่ของระบบ)) เวลาแย่ที่สุดของทั้งงาน (ทุกรอบ, การคัดกรอง, การส่ง) อยู่ใต้ `WEBHOOK_MAX_DURATION_S` ตาม [project-setup ข้อ 10.4](../architecture/project-setup.md#104-adapter-และ-route) ซึ่ง test ตรึงไว้
- Prompt caching ด้วย marker `cache_control` แบบระบุเองตัวเดียวที่บล็อกคลังความรู้ ไม่ใช้ caching อัตโนมัติ ([ai-prompt ข้อ 3](ai-prompt.md#3-โครงของ-request), [ADR 0021](../adr/0021-explicit-cache-marker-and-fallback-per-model.md))
- การสลับโมเดลสำรองฝั่ง server เมื่อโมเดลปฏิเสธคำขอ (ฟีเจอร์ beta) ใช้กับ Opus 5.5 เท่านั้นสำหรับการตอบแชท Sonnet 5.5 และ Haiku 5.5 ไม่ใช้ ([ADR 0021](../adr/0021-explicit-cache-marker-and-fallback-per-model.md))
- ต้นทุนคำนวณจากโมเดลที่ API รายงานว่าตอบจริง ดู [usage-cost](usage-cost.md)

เหตุผลอยู่ใน [ADR 0007](../adr/0007-ai-provider-port-and-default-model.md)

## งานที่ค้าง

ก่อนเรียกโมเดล ระบบตั้ง `aiState` ของ Contact เป็น `replying` พร้อมเวลา ถ้าค้างเกิน `AI_STUCK_AFTER_MS` (เช่น function ถูกตัด) รอบ polling ถัดไปของรายชื่อจะเปลี่ยนแชทเป็นรอแอดมินด้วยเหตุผล `ai_timeout` และบันทึกบรรทัดเหตุการณ์ เหตุผลเดียวกันนี้ใช้เมื่องานหนึ่งตอบครบ `AI_MAX_ROUNDS_PER_RUN` รอบแล้วยังมีข้อความของผู้ใช้ที่ไม่ได้ตอบ ข้อความของ AI ที่ค้าง "กำลังส่ง" เพราะ function ถูกตัดระหว่างส่ง เป็นส่งไม่สำเร็จด้วย `line.send_interrupted` ตาม [line-messaging](line-messaging.md#งานส่งที่ค้าง) และแอดมินกด "ส่งอีกครั้ง" ได้

## สิ่งที่ไม่ทำ

- AI อ่านรูปหรือวิดีโอ
- AI เรียกเครื่องมือ ค้นเว็บ หรือแก้ข้อมูล
- การสรุปหรือบีบอัดประวัติแชท
- AI ช่วยร่างคำตอบให้แอดมิน

## วิธีทดสอบ

- Unit ของ `GenerateAiReply` ด้วยเวลาปลอมและ adapter ปลอม: ทุกเงื่อนไข, การรวมข้อความ, kill switch ถูกปิดระหว่างทาง, งบเต็ม, คำตอบไม่ตรง schema, โมเดลปฏิเสธ, reply token หมดอายุ, ลิงก์ที่แอดมินไม่ได้เขียน, การเรียกที่ไม่ได้คำตอบ
- Unit ของเวลาแย่ที่สุด (`src/composition/timing-budget.spec.ts`)
- E2E เส้นที่ 3, 4 และ 9
- ชุดคำถามวัดคุณภาพ AI กับ Claude จริง รันเมื่อถูกสั่งเท่านั้น ดู [test-strategy](../qa/test-strategy.md)
