# Error catalog

> สถานะ: อนุมัติ · อัปเดตล่าสุด: 2026-11-19

รายการรหัส error ทั้งหมดของระบบ ที่เดียว `ERROR_CODES` ใน `src/core/domain/error-codes.ts` และตารางข้อความไทยใน `src/common/error-messages.ts` ต้องมีรหัสครบตามไฟล์นี้ ไม่มากไม่น้อยกว่า

- รหัสเป็นภาษาอังกฤษตัวเล็ก คั่นพื้นที่กับชื่อด้วยจุด และคำคั่นด้วย `_` รหัสไม่เปลี่ยนเมื่อข้อความไทยเปลี่ยน
- ข้อความไทยตาม [ux-writing](../guidelines/ux-writing.md): ไทยธรรมดา ไม่มีคำลงท้าย บอกว่าเกิดอะไรและทำอะไรต่อ ใช้คำตามอภิธานศัพท์ และไม่โทษผู้ใช้เมื่อเป็นความผิดพลาดของระบบ
- `{...}` ในข้อความคือค่าที่หน้าเว็บเติมจากข้อมูลที่มีอยู่แล้วหรือจาก constant ใน `src/contracts/` (เช่น `{maxMb}` จาก `PDF_MAX_BYTES` และ `{hours}` จาก `LINE_RETRY_KEY_WINDOW_MS`) ไม่ได้มาจาก error ค่าของ constant อยู่ใน [project-setup](project-setup.md#10-ค่าคงที่ของระบบ)
- รูปแบบ JSON ของ error อยู่ใน [api-contract](api-contract.md#รูปแบบ-error) รหัสที่ use case และ port คืนอยู่ใน [use-cases](use-cases.md) และ [domain-and-ports](domain-and-ports.md)

วิธีแสดง:

| ค่า | ความหมาย |
| --- | --- |
| inline | ข้อความใต้ช่องกรอกหรือข้างปุ่มที่เกี่ยวข้อง ข้อมูลที่กรอกยังอยู่ |
| toast | แจ้งชั่วคราวมุมจอ |
| สถานะ | แสดงเป็นส่วนหนึ่งของสิ่งที่ล้มเหลว เช่น ฟองข้อความ แถวในตาราง หรือส่วนสถานะระบบ และอยู่จนสถานะเปลี่ยน |
| ไม่แสดง | อยู่ใน log หรือใช้ภายในเท่านั้น |

HTTP เป็น "—" เมื่อรหัสไม่เคยเป็นคำตอบของ HTTP

## คำขอและระบบ

| รหัส | HTTP | เกิดเมื่อ | ข้อความที่แอดมินเห็น | แสดง |
| --- | --- | --- | --- | --- |
| `request.invalid` | 400 | Path, query หรือ body ไม่ผ่าน schema | ข้อมูลที่ส่งไม่ถูกต้อง ตรวจช่องที่กรอกแล้วลองอีกครั้ง | inline |
| `request.too_large` | 413 | Body เกินเพดานของ endpoint | ข้อมูลใหญ่เกินที่ระบบรับได้ ลดขนาดแล้วลองอีกครั้ง | toast |
| `request.origin_forbidden` | 403 | Method ที่แก้ข้อมูลมาจากต้นทางอื่น | คำขอนี้ไม่ได้มาจากหน้าเว็บของระบบ โหลดหน้าใหม่แล้วลองอีกครั้ง | toast |
| `internal.unexpected` | 500 | Exception ที่ไม่คาดคิด หรือฐานข้อมูลล่มระหว่างคำขอ และใช้เป็นเหตุผลของไฟล์ในคลังความรู้ที่แปลงแล้วระบบพัง | ทั่วไป: เกิดข้อผิดพลาดในระบบ ลองอีกครั้ง ในฟอร์ม: บันทึกไม่สำเร็จ ข้อมูลที่กรอกยังอยู่ ลองอีกครั้ง ในคลังความรู้: แปลงไฟล์ไม่สำเร็จเพราะระบบขัดข้อง กด "ลองใหม่" | toast, inline ในฟอร์ม, สถานะในตารางไฟล์ |
| `db.unavailable` | 503 | `GET /api/health` ต่อฐานข้อมูลไม่ได้ หรือ webhook ที่ signature ถูกแต่บันทึก event ใดในก้อนไม่ได้เลยเพราะฐานข้อมูลล่ม (ให้ LINE ส่งซ้ำ [line-messaging](../specs/line-messaging.md#รับ-event-webhook) ข้อ 6) | ไม่แสดง (ส่วนสถานะระบบแสดงสถานะผิดพลาดเมื่อเรียก API ไม่ได้) | ไม่แสดง |
| `storage.unavailable` | 503 | ที่เก็บไฟล์ตอบผิดพลาดหรือไม่ตอบ | ที่เก็บไฟล์ใช้งานไม่ได้ชั่วคราว ลองอีกครั้งในอีกสักครู่ | inline ที่ไฟล์แนบ |
| `secret.decrypt_failed` | — | `SecretCipher` ถอดรหัสไม่ได้ use case แปลงเป็น `line.credentials_unreadable` | ไม่แสดง | ไม่แสดง |

## รหัสเข้าใช้

| รหัส | HTTP | เกิดเมื่อ | ข้อความที่แอดมินเห็น | แสดง |
| --- | --- | --- | --- | --- |
| `access.unauthorized` | 401 | ไม่มี cookie หรือ cookie หมดอายุหรือถูกแก้ | ไม่มีข้อความ หน้าเว็บพากลับหน้ายินดีต้อนรับ | สถานะ |
| `access.code_invalid` | 401 | รหัสเข้าใช้ไม่ตรง | รหัสไม่ถูกต้อง ลองอีกครั้ง | inline |
| `access.rate_limited` | 429 | ลองรหัสผิดครบ `RATE_LIMIT_UNLOCK` ในหน้าต่างเดียวจาก IP เดียว หรือครบ `RATE_LIMIT_UNLOCK_NO_IP` รวมทุกคำขอที่ไม่มี IP | ลองหลายครั้งเกินไป รอสักครู่แล้วลองใหม่ | inline |

ช่องรหัสว่างไม่ถูกส่งถึง server หน้าเว็บแสดง "กรุณาใส่รหัสเข้าใช้" ตาม [access-gate](../specs/access-gate.md#กรณีผิดพลาดและกรณีขอบ) ซึ่งไม่ใช่รหัส error

| `line.rate_limited` | — | LINE ตอบ 429 จนหมดจำนวน retry | ส่งไม่สำเร็จ LINE รับคำขอถี่เกินไป รอสักครู่แล้วกด "ส่งอีกครั้ง" | สถานะ |

| `line.reply_failed` | — | LINE ปฏิเสธ reply ด้วยเหตุผลอื่นนอกจาก token ใช้ไม่ได้ เช่น 400 ที่ข้อความไม่ใช่ `Invalid reply token` (body ผิดรูป) ระบบไม่ push payload เดิมต่อ | ส่งไม่สำเร็จ LINE ไม่รับข้อความนี้ กด "ส่งอีกครั้ง" | สถานะ |
| `line.unavailable` | 503 | เครือข่ายล่ม, timeout หรือ 5xx จาก LINE หลัง retry | ส่งไม่สำเร็จ ติดต่อ LINE ไม่ได้ กด "ส่งอีกครั้ง" ในหน้าตั้งค่า: ติดต่อ LINE ไม่ได้ ลองอีกครั้งในอีกสักครู่ | สถานะ, inline ในหน้าตั้งค่า |

## ไฟล์แนบและสื่อ

| รหัส | HTTP | เกิดเมื่อ | ข้อความที่แอดมินเห็น | แสดง |
| --- | --- | --- | --- | --- |
| `upload.rate_limited` | 429 | ขอสิทธิ์อัปโหลดเกิน `RATE_LIMIT_UPLOAD_TICKET` | อัปโหลดถี่เกินไป รอสักครู่แล้วแนบใหม่ | inline ที่ไฟล์แนบ |

| `upload.not_found` | 409 | ส่งข้อความด้วย uploadId ที่ยังไม่มีไฟล์ครบ | ไฟล์ที่แนบอัปโหลดไม่ครบ แนบไฟล์ใหม่อีกครั้ง | inline |
| `upload.content_mismatch` | 422 | เนื้อไฟล์ไม่ตรงกับชนิดที่ประกาศ | เนื้อไฟล์ไม่ตรงกับชนิดของไฟล์ แนบไฟล์อื่น | inline |
| `upload.signature_invalid` | 403 | ลายเซ็นของการอัปโหลดบนดิสก์ในเครื่องไม่ถูกต้อง | อัปโหลดไม่สำเร็จ แนบไฟล์ใหม่อีกครั้ง | inline |
| `upload.expired` | 403 | สิทธิ์อัปโหลดเกิน `UPLOAD_TICKET_TTL_MS` | สิทธิ์อัปโหลดหมดเวลา แนบไฟล์ใหม่อีกครั้ง | inline |
| `media.too_large` | 413 | ไฟล์ขาเข้าจาก LINE หรือไฟล์ที่ PUT เข้าดิสก์เกินเพดาน | ขาเข้า: ไฟล์ใหญ่เกินกว่าที่ระบบเก็บได้ ขาออก: ไฟล์ใหญ่เกินไป แนบไฟล์ที่เล็กกว่า | สถานะ (ป้ายบนฟอง), inline |
| `media.not_found` | 404 | ไม่มีไฟล์บนดิสก์ในเครื่องตาม URL | ไม่แสดงรหัส ภาพแสดง "โหลดรูปไม่สำเร็จ" | สถานะ |

สถานะสื่อขาเข้า (`MediaStatus`) ไม่ใช่รหัส error ข้อความของ `pending`, `failed` และ `too_large` เป็นถ้อยคำบนหน้าจอใน [ui-copy](../specs/ui-copy.md) (`inbox.media.*`)

## เหตุผลของสถานะรอแอดมิน

ไม่ใช่รหัส error แต่เป็นค่าที่หน้าเว็บต้องแปล ไฟล์นี้เป็นเจ้าของข้อความไทยของ `HandoffReason` และ `EventCode` ทุกค่า ([domain-and-ports](domain-and-ports.md#enum)) ส่วน [ui-copy](../specs/ui-copy.md) ลิงก์มาที่นี่ ในโค้ดอยู่ใน `src/common/error-messages.ts` ด้วยฟังก์ชัน `handoffReasonText(reason)` และ `eventCodeText(code)` ข้อความเดียวกันใช้ทั้งบรรทัดรองในส่วนหัวของแชท แผงข้อมูล และบรรทัดเหตุการณ์ `handoff.{reason}`

| ค่า | ข้อความ | เกิดเมื่อ |
| --- | --- | --- |
| `customer_sent_image` | ลูกค้าส่งรูป AI จึงหยุดรอแอดมิน | ลูกค้าส่งรูปขณะ AI ตอบแทนเปิด |
| `customer_sent_video` | ลูกค้าส่งวิดีโอ AI จึงหยุดรอแอดมิน | ลูกค้าส่งวิดีโอขณะ AI ตอบแทนเปิด |
| `customer_sent_non_text` | ลูกค้าส่งข้อความที่ไม่ใช่ตัวอักษร AI จึงหยุดรอแอดมิน | สติกเกอร์ เสียง ไฟล์ ตำแหน่ง หรือชนิดอื่น |
| `budget_reached` | งบ AI ของวันนี้เต็ม | งบต่อวันถึงเพดานตาม [usage-cost](../specs/usage-cost.md#งบต่อวัน) |
| `ai_not_in_knowledge` | AI ไม่พบคำตอบในคลังความรู้ จึงหยุดรอแอดมิน | โมเดลตอบ `handoffReason` เป็น `not_in_knowledge` |
| `ai_needs_human_action` | ลูกค้าขอเรื่องที่ต้องให้คนจัดการ AI จึงหยุดรอแอดมิน | `needs_human_action` |
| `ai_unsafe_or_offtopic` | ลูกค้าคุยนอกเรื่องหรือใช้คำไม่เหมาะสม AI จึงหยุดรอแอดมิน | `unsafe_or_offtopic` |
| `ai_other` | AI ตอบเรื่องนี้ไม่ได้ จึงหยุดรอแอดมิน | `other` |
| `ai_failed` | AI ตอบไม่สำเร็จ จึงหยุดรอแอดมิน ดูรายละเอียดที่ ตั้งค่า › สถานะระบบ | เรียกโมเดลไม่สำเร็จ, โมเดลปฏิเสธ, คำตอบถูกตัดหรือไม่ตรง schema, ส่งคำตอบไม่สำเร็จ |
| `ai_timeout` | AI ตอบไม่ทันเวลา จึงหยุดรอแอดมิน | `aiState` ค้างเกิน `AI_STUCK_AFTER_MS` หรือยังมีข้อความของลูกค้าที่ไม่ได้ตอบเมื่องานตอบครบ `AI_MAX_ROUNDS_PER_RUN` รอบแล้ว |
| ค่าที่หน้าเว็บไม่รู้จัก | แชทนี้รอแอดมิน | ใช้เป็นค่าสำรองเท่านั้น |

## บรรทัดเหตุการณ์

บรรทัดเหตุการณ์คือแถว Message ชนิด `event` (`direction` `internal`, `author` `system`) ที่มี `eventCode` แสดงในแชทตามตำแหน่งของเวลาที่บันทึก ([ui-screens](../specs/ui-screens.md#53-พื้นที่ข้อความ))

| `eventCode` | ข้อความ |
| --- | --- |
| `handoff.{reason}` | ข้อความของ `reason` ในตารางข้างบน |
| `ai.turned_off_by_admin` | คุณตอบเอง AI ตอบแทนของลูกค้าคนนี้จึงปิด เปิดอีกครั้งได้ที่สวิตช์ด้านบน |
| `guard.blocked` | นอกขอบเขตหัวข้อ AI จึงไม่ตอบ |
| `contact.followed` | ลูกค้าเพิ่มเพื่อน |
| `contact.unfollowed` | ลูกค้าเลิกติดตามแล้ว |
| ค่าที่หน้าเว็บไม่รู้จัก | ไม่แสดงบรรทัดนั้น |
