# 0031: หน้าตั้งค่าแบบแท็บ ช่อง LINE ที่ล็อก คำว่า "ผู้ใช้" prompt ที่ไม่สมมติว่าเป็นร้าน ข้อความปฏิเสธที่บอกหัวข้อ และการดึงโปรไฟล์วันละครั้ง

> สถานะ: อนุมัติ · วันที่: 2026-11-19
> เสริม [ADR 0024](0024-scope-reductions.md) (ข้อความปฏิเสธยังตั้งค่าไม่ได้ แต่บอกชื่อหัวข้อ) และ [ADR 0026](0026-neutral-core-prompt-and-layered-settings.md) (แกนของคำสั่งที่เป็นกลาง)

## บริบท

- หน้าตั้งค่าเป็นหน้ายาวหน้าเดียวเจ็ดส่วน แอดมินต้องเลื่อนนานกว่าจะถึงส่วนที่ต้องการ ปุ่มบันทึกของชื่อ AI ปรากฏเฉพาะเมื่อพิมพ์ ช่องจึงขยับ คอลัมน์ control ของแต่ละแถวกว้างไม่เท่ากัน และคำว่า "ขอบเขตคำตอบ" อยู่ใน AI ทั้งที่เป็นเรื่องของความรู้ที่ใช้ตอบ
- ช่อง Channel secret และ Channel access token ว่างเสมอ แอดมินไม่รู้ว่ามีค่าบันทึกอยู่หรือไม่ และการบันทึกต้องกรอกทั้งสามค่าใหม่ทุกครั้งแม้จะเปลี่ยนแค่ token
- แอปเป็นเครื่องมือทดสอบ LINE OA ที่ใช้ได้กับบัญชีทุกแบบ แต่หน้าจอ ข้อความที่ส่งทาง LINE และ prompt เรียกคนที่ทักมาว่า "ลูกค้า"
- บน production ที่คลังความรู้ว่างและตั้งค่าเป็นกลาง AI ตอบว่า "คลังความรู้ของร้านยังไม่มีข้อมูล ... ยังตอบเรื่องสินค้าหรือบริการของร้านไม่ได้" ทั้งที่แกนของคำสั่งไม่มีคำว่าร้าน ตัวอย่างในแกนเป็นของการค้า (ราคา เวลาทำการ จอง สั่งซื้อ คืนเงิน ส่วนลด ของแถม) และคำว่าลูกค้า น่าจะพาโมเดลไปสมมติว่าเป็นร้าน
- เมื่อขอบเขตหัวข้อเปิด ข้อความที่ถูกกันได้ "คุยได้เฉพาะหัวข้อที่กำหนดไว้นะคะ" เสมอ แม้ผู้ใช้ถามว่า "หัวข้ออะไร" ผู้ใช้จึงไม่มีทางรู้ว่าถามอะไรได้
- รูปโปรไฟล์ของผู้ใช้บางคนอยู่บน `sprofile.line-scdn.net` ซึ่ง CSP ไม่อนุญาต จึงขึ้นเป็นตัวอักษรย่อ และระบบดึงโปรไฟล์เฉพาะครั้งแรกที่เห็นผู้ใช้ ชื่อหรือรูปที่เปลี่ยนภายหลังจึงไม่เคยขึ้น

## การตัดสินใจ

1. **หน้าตั้งค่าแบบแท็บ** ห้าแท็บ: AI, ความรู้และขอบเขต, LINE, ค่าใช้จ่าย, สถานะระบบ แต่ละแท็บเป็นการ์ด แท็บที่เปิดอยู่ใน `?tab=` (โหลดใหม่และปุ่มย้อนกลับใช้ได้) ไม่ระบุแท็บเปิด AI เว้นแต่ยังไม่ได้เชื่อม LINE ซึ่งเปิด LINE mount เฉพาะแท็บที่เปิด query ของแท็บอื่นจึงไม่โหลดและไม่ polling ขอบเขตคำตอบย้ายไปอยู่บนสุดของการ์ด "ความรู้ที่ใช้ตอบ" คู่กับคลังความรู้ ([ui-screens ข้อ 9.2](../specs/ui-screens.md#92-โครงร่วม))
2. **ปุ่มบันทึกของช่องอยู่เสมอ** เป็นปุ่มรองที่กดไม่ได้เมื่อค่ายังไม่เปลี่ยน และเป็นปุ่มหลักเมื่อเปลี่ยน ทุก control ในการ์ดใช้คอลัมน์ขวากว้างเท่ากัน คำลงท้ายเป็น segmented control สองตัวที่เต็มคอลัมน์ ([ux-writing](../guidelines/ux-writing.md#ปุ่ม))
3. **ช่อง LINE ที่บันทึกแล้วล็อก** Webhook URL เป็นช่องอ่านอย่างเดียว Channel ID ที่บันทึกแสดงค่าในช่องที่ล็อก สองค่าลับแสดงเครื่องหมาย • จำนวนคงที่ที่ไม่มาจากค่าจริงและไม่บอกความยาว ปุ่มดินสอเปิดแก้ทีละช่องและกลายเป็นปุ่ม X ที่ยกเลิก ระบบส่งเฉพาะช่องที่แก้ `PUT /api/settings/line-credentials` รับบางค่าได้ (อย่างน้อยหนึ่ง) server เติมค่าที่เหลือจากที่บันทึกไว้แล้วตรวจกับ LINE ทั้งสามค่าเหมือนเดิม รวมการตรวจว่าเป็น channel เดียวกัน ([use-cases SetLineCredentials](../architecture/use-cases.md#setlinecredentials))
4. **ใช้ "ผู้ใช้" ไม่ใช้ "ลูกค้า"** ในทุกที่ที่คนอ่าน: หน้าจอ ข้อความที่ส่งทาง LINE prompt และเอกสาร ชื่อในโค้ด ค่าใน enum และรหัสเหตุการณ์ (`customer`, `customer.tapped_*`) คงเดิม ADR เก่าคงถ้อยคำเดิมเพราะเป็นบันทึกของเวลานั้น ([ux-writing](../guidelines/ux-writing.md#กฎถ้อยคำบนหน้าจอ))
5. **แกนของคำสั่งไม่สมมติว่าเป็นร้าน** เพิ่มกฎใต้ "ตัวตน" ว่าอย่าสมมติหรือพูดว่าบัญชีเป็นร้าน ธุรกิจ หรือองค์กร และอย่าพูดถึงสินค้า บริการ หรือ "ร้าน" เว้นแต่คำแนะนำสำหรับ AI หรือคลังความรู้บอกไว้ เพิ่มกฎการตอบคำถาม "ตอบเรื่องอะไรได้บ้าง" ตามขอบเขตคำตอบจริง (ไม่ส่งต่อแอดมินเพราะคำถามนี้) และเปลี่ยนตัวอย่างของการค้าเป็นตัวอย่างที่เป็นกลาง โดยพฤติกรรมเดิมคงอยู่: ข้อมูลเฉพาะของบัญชีต้องมาจากคลังความรู้ และเรื่องที่ต้องให้คนทำยังส่งต่อแอดมิน ([ai-prompt ข้อ 2.2](../specs/ai-prompt.md#22-แม่แบบ))
6. **ข้อความปฏิเสธบอกชื่อหัวข้อ** `guardRefusalText(particle, topics)` = `ตอนนี้คุยได้เฉพาะเรื่อง “ก” และ “ข” นะคะ` บอกไม่เกิน `GUARD_REFUSAL_MAX_TOPICS` หัวข้อ ที่เกินเป็น "และเรื่องอื่น ๆ" ข้อความยังตั้งค่าไม่ได้ตาม ADR 0024 คำถามที่ถามเพียงว่าคุยเรื่องอะไรได้บ้างผ่านการคัดกรองแบบเดียวกับคำทักทาย แล้วบล็อก `<topic_guard>` ให้ผู้ช่วยบอกหัวข้อและชวนเลือก หน้าตั้งค่าบอกแอดมินว่าใช้คำกว้าง ๆ ได้และผู้ใช้จะเห็นชื่อหัวข้อ ([topic-guard](../specs/topic-guard.md))
7. **รูปโปรไฟล์จากทั้งสอง host ของ LINE** `img-src` ของ CSP เพิ่ม `https://sprofile.line-scdn.net` คู่กับ `https://profile.line-scdn.net` เฉพาะ host นั้น ไม่ใช้ wildcard ([pitfalls S7](../guidelines/pitfalls-and-prevention.md#s7-รูปโปรไฟล์ของ-line-ไม่ขึ้นเพราะ-host-ไม่อยู่ใน-csp))
8. **ดึงโปรไฟล์ใหม่อย่างมากวันละครั้ง** คอลัมน์ `Contact.profileFetchedAt` (migration ที่สิบสอง เพิ่มอย่างเดียว) เก็บเวลาที่ลองดึงครั้งล่าสุด ทั้งเมื่อสำเร็จและไม่สำเร็จ event ของผู้ใช้ที่มีอยู่แล้ว (ข้อความ การกดปุ่ม follow) ได้งานหลังตอบ 200 ซึ่งจองการลองด้วย compare-and-set คำสั่งเดียวเมื่อการลองล่าสุดเก่ากว่า `PROFILE_REFRESH_AFTER_MS` (24 ชั่วโมง) แล้วจึงเรียก LINE สำเร็จแทนชื่อและรูป (รูป null ล้างรูปเดิม) ไม่สำเร็จคงค่าเดิมและลองใหม่ในอีก 24 ชั่วโมง ([line-messaging](../specs/line-messaging.md#โปรไฟล์ของผู้ใช้))

## ทางเลือกที่พิจารณา

- หน้ายาวพร้อมสารบัญที่เลื่อนไปยังส่วน: ยังโหลดและ polling ทุกส่วนพร้อมกัน และหน้ายังยาวบนมือถือ
- แสดงค่าลับบางส่วน เช่น สี่ตัวท้าย: หลุดข้อมูลของความลับและบอกความยาว ขัดกับหลักไม่คืนค่าลับ
- ให้ช่องลับว่างและบันทึกทั้งสามค่าทุกครั้งเหมือนเดิม: แอดมินต้องหาค่าที่ไม่ได้ตั้งใจเปลี่ยนมาใส่ใหม่ และไม่เห็นว่ามีค่าอยู่แล้ว
- ข้อความปฏิเสธที่แอดมินตั้งเอง: ถูกตัดออกแล้วใน ADR 0024 และไม่แก้ปัญหาว่าหัวข้อเปลี่ยนแต่ข้อความไม่เปลี่ยน
- ดึงโปรไฟล์ทุกข้อความ: เรียก LINE บ่อยเกินจำเป็น ดึงภายใน request: ทำให้ webhook ช้า ลองใหม่เร็วขึ้นเมื่อดึงไม่สำเร็จ (เช่นทุกชั่วโมง): ผู้ใช้ที่บล็อกบัญชีได้ 404 ทุกครั้ง จึงใช้ค่าเดียว 24 ชั่วโมงทั้งสองกรณีเพื่อให้เรียบง่าย
- ตัดสินว่าต้องดึงโปรไฟล์หรือไม่ใน request (อ่าน `profileFetchedAt` ผ่าน entity): ต้องเพิ่ม field ให้ entity และเขียนฐานข้อมูลก่อนตอบ จึงให้งานหลังตอบตัดสินเองด้วย UPDATE แบบมีเงื่อนไขคำสั่งเดียว ซึ่งไม่เขียนอะไรเมื่อยังไม่ถึงเวลา

## ผลที่ตามมา

- ทุก event ของผู้ใช้ที่มีอยู่แล้วได้งานหลังตอบหนึ่งงานที่ส่วนใหญ่จบด้วย UPDATE ที่ไม่ตรงแถวใด งานนี้สั้นกว่างาน AI และงานสื่อ จึงไม่เปลี่ยนเวลาแย่ที่สุดของ webhook ([project-setup ข้อ 10.4](../architecture/project-setup.md#104-adapter-และ-route))
- หลัง deploy ผู้ใช้ที่มีอยู่ทุกคนมี `profileFetchedAt` เป็น NULL จึงได้โปรไฟล์ใหม่เมื่อทักมาครั้งถัดไป
- การเปลี่ยน prompt ทั้งแกนของคำสั่งและของขอบเขตหัวข้อยังไม่ได้วัดกับโมเดลจริง ต้องรันชุดคำถามวัดคุณภาพเมื่อเจ้าของงานสั่ง ([ai-prompt ข้อ 8](../specs/ai-prompt.md#8-ชุดคำถามวัดคุณภาพ-ai)) ชุดคำถามยังไม่มีข้อของคำถาม "ตอบเรื่องอะไรได้บ้าง" และข้อความปฏิเสธที่บอกหัวข้อ
- E2E ของหน้าตั้งค่าเปิดแท็บผ่าน `?tab=` และมีเส้นที่ 16 สำหรับแท็บและช่องที่ล็อก

## จะทบทวนเมื่อ

- ชุดคำถามวัดคุณภาพพบว่าโมเดลยังสมมติว่าเป็นร้าน หรือคำถาม "หัวข้ออะไร" ยังถูกกัน
- LINE เปลี่ยน host ของรูปโปรไฟล์อีก หรือข้อจำกัดอัตราของ profile API ทำให้วันละครั้งมากเกินไป
- หน้าตั้งค่ามีแท็บมากกว่าห้าแท็บ
