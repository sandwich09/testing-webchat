# 0010: ใช้ reply token ก่อน push และกันการส่งซ้ำ

> สถานะ: อนุมัติ · วันที่: 2026-11-18

## บริบท

Push message ของ LINE มีโควตารายเดือน ส่วน reply ไม่กินโควตาแต่ token มีอายุสั้น LINE ส่ง webhook ซ้ำได้ และแอดมินอาจกดส่งซ้ำ

## การตัดสินใจ

ทุกการส่งใช้ reply token ของลูกค้าถ้ายังใช้ได้ ไม่เช่นนั้น push พร้อม `X-Line-Retry-Key` ที่เป็นค่าเดิมของข้อความนั้น ขาเข้ากันซ้ำด้วย unique ของ `webhookEventId` และ `lineMessageId` ขาออกใช้ id ที่หน้าเว็บสร้างเป็น primary key

## ทางเลือกที่พิจารณา

- Push อย่างเดียว: ง่ายกว่า แต่โควตาหมดเร็ว
- ดัก error ของ unique constraint แล้วเดาว่าตัวไหนชน: Prisma 7 กับ adapter นี้ไม่บอกชื่อ constraint

## ผลที่ตามมา

AI ซึ่งตอบภายในไม่กี่วินาทีมักใช้ reply ได้ จึงประหยัดโควตา และลูกค้าไม่ได้รับข้อความซ้ำ แลกกับตรรกะการเลือกช่องทางที่ต้องทดสอบ

## จะทบทวนเมื่อ

LINE เปลี่ยนเงื่อนไขของ reply token หรือโควตา
