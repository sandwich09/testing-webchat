# 0026: แกนของคำสั่งที่เป็นกลาง คำแนะนำสำหรับ AI ขอบเขตคำตอบ ชื่อ AI การทักทายผ่านขอบเขตหัวข้อ และโมเดลเริ่มต้น

> สถานะ: อนุมัติ เสริมโดย [0031](0031-settings-tabs-user-wording-and-neutral-prompt.md) (กฎไม่สมมติว่าเป็นร้าน) · วันที่: 2026-11-19
> แทนแม่แบบคำสั่งระบบก่อนหน้านี้ใน [ai-prompt ข้อ 2](../specs/ai-prompt.md#2-คำสั่งระบบ) ที่ใช้ชื่อ LINE OA เป็นชื่อร้าน, แทนโมเดลเริ่มต้นของ [ADR 0007](0007-ai-provider-port-and-default-model.md) และเสริม [ADR 0020](0020-topic-guardrail-as-separate-check.md) เรื่องคำทักทาย

## บริบท

เจ้าของงานทดสอบ production ครั้งแรกกับ LINE Official Account และ Claude จริง ระบบนี้เป็น webchat ของ LINE OA ที่เป็นกลางสำหรับทดสอบฟรี ไม่ใช่ผลิตภัณฑ์ของร้านค้า และ production ไม่มี seed แต่แม่แบบเดิมขึ้นต้นว่า "ผู้ช่วย AI ของร้าน {ชื่อ LINE OA}" บังคับให้ตอบจากคลังความรู้เท่านั้น ให้พาเรื่องกลับมาที่ร้านเสมอ และส่งทุกคำถามที่ไม่มีในคลังให้แอดมิน บัญชีที่ไม่ใช่ร้านหรือยังไม่มีคลังความรู้จึงได้ AI ที่ตอบแทบอะไรไม่ได้ เมื่อเปิดขอบเขตหัวข้อ คำทักทายก็ถูกกัน ผู้ช่วยจึงแนะนำตัวไม่ได้ และโมเดลเริ่มต้น Opus 5.5 แพงเกินไปสำหรับเครื่องมือทดสอบ

## การตัดสินใจ

1. แกนของคำสั่งระบบเป็นข้อความที่เจ้าของงานอนุมัติ เป็นกลาง ไม่ใส่ชื่อ LINE OA และไม่สมมติว่าเป็นร้าน บทบาท น้ำเสียง เรื่องที่คุยได้ คำทักทาย และข้อห้ามเพิ่มเติมมาจากคำแนะนำสำหรับ AI (`Settings.aiInstructions` ในบล็อก `<custom_instructions>`) ค่าเริ่มต้นว่าง ซึ่งลบล้าง `<rules>` ไม่ได้
2. ตั้งค่าใหม่ "ชื่อ AI" (`Settings.aiName`) ไม่บังคับ ตัดช่องว่าง บรรทัดเดียว ไม่เกิน `AI_NAME_MAX_CHARS` ใช้ตามที่พิมพ์ ว่างแล้วใช้บรรทัด "ไม่มีชื่อเฉพาะ"
3. ตั้งค่าใหม่ "ขอบเขตคำตอบ" (`Settings.aiAnswerMode`: `knowledge_only` หรือ `general`) เลือกบรรทัดของ "ข้อมูลที่ใช้ตอบ" ค่าเริ่มต้นของระบบที่ติดตั้งใหม่คือ `general` เพราะเครื่องมือทดสอบที่ยังไม่มีคลังความรู้ต้องคุยได้ทันที ในโหมดนี้คำถามที่ไม่อยู่ในคลังไม่ใช่การส่งต่อแอดมิน ยกเว้นข้อมูลเฉพาะของบัญชี กฎลิงก์และการตรวจคำตอบอื่นไม่เปลี่ยน
4. กฎการทักทาย: ผู้ใช้ทักทายและยังไม่เคยแนะนำตัวในประวัติที่เห็น ผู้ช่วยแนะนำตัวในประโยคเดียว (บอกชื่อเมื่อตั้งไว้)
5. เมื่อขอบเขตหัวข้อเปิด คำทักทาย ขอบคุณ และบอกลาสั้น ๆ ที่ไม่มีคำขออื่นผ่านการคัดกรอง (`allowed: true`, `matchedTopic: null`) ข้อความที่มีคำทักทายร่วมกับคำขอตัดสินจากคำขอ การแยกอยู่ใน prompt ของตัวคัดกรองและบล็อก `<topic_guard>` ไม่ใช่การเทียบคำในโค้ด schema ไม่เปลี่ยน และความล้มเหลวยังปิดแบบปลอดภัย
6. โมเดลเริ่มต้นของระบบที่ติดตั้งใหม่เป็น `claude-sonnet-5-5` เปลี่ยนเฉพาะค่าเริ่มต้นของคอลัมน์ แถว Settings ที่มีอยู่แล้วคงค่าเดิม แอดมินเปลี่ยนเองในหน้าตั้งค่า
7. ชื่อเรียกภายในเลิกใช้ "shop": slot เป็น `{identityLine}`, `{introduceName}`, `{answerScope}`, `{customInstructions}`, `ChatRole` เป็น `customer | assistant`, บรรทัดเวลาเป็น "เวลาปัจจุบัน:" และป้ายในประวัติกับบริบทของตัวคัดกรองเป็น "ผู้ใช้" กับ "แอดมิน"/"ผู้ช่วย" บล็อก `<output>` คงเดิม

## ทางเลือกที่พิจารณา

- คงชื่อ LINE OA เป็นชื่อร้านแล้วเพิ่มแค่ชื่อ AI: ยังสมมติว่าเป็นร้าน และชื่อ OA ที่ตั้งเพื่อทดสอบกลายเป็นตัวตนของ AI โดยแอดมินไม่ได้เลือก
- ค่าเริ่มต้น `knowledge_only`: ตรงกับพฤติกรรมเดิม แต่ระบบที่ติดตั้งใหม่ไม่มีคลังความรู้ AI จึงส่งเกือบทุกข้อความให้แอดมิน ซึ่งไม่ตรงกับเครื่องมือทดสอบที่เป็นกลาง
- ตรวจคำทักทายด้วยรายการคำในโค้ดก่อนเรียกตัวคัดกรอง: ภาษาไทยทักทายได้หลายแบบ คำทักทายที่มีคำขอพ่วงจะหลุด และเป็นรายการคำต้องห้ามแบบกลับด้านที่ ADR 0020 ปฏิเสธไว้แล้ว
- เพิ่ม field `courtesy` ใน schema ของตัวคัดกรอง: เพิ่มสัญญาโดยไม่มีผู้ใช้ค่า เพราะ backend ทำเหมือนกันกับผลที่ผ่าน
- Migration ที่แก้ `aiModel` ของแถวเดิมเป็น Sonnet: เขียนทับค่าที่แอดมินอาจเลือกไว้ ไม่เป็นแบบเพิ่มอย่างเดียว

## ผลที่ตามมา

- Migration ที่หกเพิ่ม enum `AiAnswerMode`, คอลัมน์ `aiName` (ว่างได้) และ `aiAnswerMode` (ค่าเริ่มต้น `general` แถวเดิมจึงได้ `general` ด้วย) และเปลี่ยนค่าเริ่มต้นของ `aiModel` ([data-model](../architecture/data-model.md#migration-ที่หก-ชื่อ-ai-ขอบเขตคำตอบ-และโมเดลเริ่มต้น))
- Production ของเจ้าของงานยังเป็น Opus 5.5 จนกว่าจะเปลี่ยนในหน้าตั้งค่า
- การตอบแชทของ Sonnet 5.5 ไม่ใช้การสลับโมเดลสำรองฝั่ง server ([ADR 0021](0021-explicit-cache-marker-and-fallback-per-model.md)) เมื่อโมเดลปฏิเสธ แชทขึ้นรอแอดมินทันที เวลาแย่ที่สุดของงานไม่ขึ้นกับโมเดล
- ความเป็นร้านของ seed และชุดคำถามวัดคุณภาพย้ายไปอยู่ในค่าตัวอย่าง `e2e/fixtures/kb/tonhom-cafe.settings.ts` (ชื่อ AI และคำแนะนำ) ชุดคำถามมีรอบที่ 3 สำหรับค่าเริ่มต้นที่เป็นกลาง และข้อ G6, G7 ของคำทักทาย ([ai-prompt ข้อ 8](../specs/ai-prompt.md#8-ชุดคำถามวัดคุณภาพ-ai)) ผลของแม่แบบใหม่กับ Claude จริงยังไม่ได้วัด
- คำสั่งระบบเปลี่ยนเมื่อแอดมินแก้ชื่อ AI หรือขอบเขตคำตอบ cache ของคำสั่งจึงเริ่มใหม่ครั้งเดียวหลังแก้

## จะทบทวนเมื่อ

ชุดคำถามวัดคุณภาพกับ Claude จริงแสดงว่าโหมด `general` ตอบข้อมูลเฉพาะของบัญชีเอง หรือคำทักทายที่มีคำขอพ่วงหลุดการคัดกรองบ่อย
