# 0022: IP ของผู้เรียกจากค่าสุดท้ายของ x-forwarded-for

> สถานะ: อนุมัติ · วันที่: 2026-11-19

## บริบท

การจำกัดความถี่ของการลองรหัสเข้าใช้ ([ADR 0006](0006-shared-access-code.md)) นับต่อ IP route ของ Next.js ไม่รู้ address ของ socket จึงต้องอ่านจาก header เดิมอ่านค่าแรกของ `x-forwarded-for` แล้ว `x-real-ip` ซึ่งเป็นค่าที่ผู้เรียกเขียนเองได้ ถ้า proxy ต่อท้าย header แทนการแทนที่ สคริปต์เดารหัสจะเปลี่ยนค่าแรกทุกครั้งและได้ถังใหม่ทุกคำขอ และคำขอที่ไม่มี IP ทุกคำขอตกอยู่ใน subject `unknown` ถังเดียว ยังไม่ได้ยืนยันว่า Vercel แทนที่หรือต่อท้าย header นี้

## การตัดสินใจ

- อ่านเฉพาะค่าสุดท้ายของ `x-forwarded-for` ซึ่งเป็นค่าที่ proxy ที่อยู่ใกล้ที่สุดเขียน: บน Vercel คือ IP ที่ edge เห็น ไม่ว่า edge จะแทนที่หรือต่อท้าย ส่วน `next start` ที่ไม่มี proxy เติมจาก socket เมื่อคำขอไม่มี header ไม่อ่าน `x-real-ip`
- ค่าที่ไม่ใช่ IP ถือว่าไม่มี IP IPv4-mapped IPv6 ใช้ IPv4 และ IPv6 ใช้ network /64
- คำขอที่ไม่มี IP ของการลองรหัสนับรวมในถังแยก `unlock_no_ip` ที่เข้มกว่า (`RATE_LIMIT_UNLOCK_NO_IP`) และ log `access.unlock.client_ip_missing` ทุกครั้ง ผู้ที่มี IP ไม่ได้รับผลเมื่อถังนี้เต็ม

รายละเอียดอยู่ใน [infrastructure](../architecture/infrastructure.md#ip-ของผู้เรียก) โค้ดอยู่ที่ `clientIpOf` ใน `src/composition/http-request.ts` และ `makeUnlockAccess`

## ทางเลือกที่พิจารณา

- ค่าแรกของ `x-forwarded-for`: ถูกเฉพาะเมื่อ proxy แทนที่ header ถ้าต่อท้าย ผู้เรียกเลือก key เองได้
- `x-real-ip` หรือ `x-vercel-forwarded-for`: ผูกกับ platform และยังไม่ได้ยืนยันว่าผู้เรียกปลอมไม่ได้ ค่าสุดท้ายของ `x-forwarded-for` ถูกทั้งสองกรณี
- ปฏิเสธทุกคำขอที่ไม่มี IP: ถ้า proxy เลิกส่ง header ทุกคนเข้าระบบไม่ได้เลย ผลเท่ากับถังเดียวที่เต็มตลอด
- ไม่จำกัดคำขอที่ไม่มี IP: เดารหัสได้ไม่จำกัด
- ถังเดียวกับคำขอที่มี IP (`unknown` เดิม): ใช้ได้ แต่ค่าจำกัดเท่ากับของ IP เดียว และไม่มี log ที่บอกว่า proxy เลิกส่ง IP

## ผลที่ตามมา

สคริปต์ที่ปลอม header ไม่ได้ถังใหม่ ส่วนผู้ที่มี IPv6 ทั้ง /64 ถูกนับรวมกัน ซึ่งยอมรับได้เพราะร้านมีแอดมินไม่กี่คน ใน Docker และเครื่อง dev ไม่มี proxy ผู้เรียกที่ส่ง header เองยังเลือก key ได้ ซึ่งยอมรับเพราะไม่เปิดสู่สาธารณะ พฤติกรรมจริงของ Vercel ยังต้องยืนยันตาม [implementation-plan](../plans/implementation-plan.md#สิ่งที่ต้องยืนยันก่อนหรือระหว่างสร้าง)

## จะทบทวนเมื่อ

ยืนยันบน Vercel แล้วพบว่าค่าสุดท้ายไม่ใช่ IP ของผู้เรียก หรือมี proxy อีกชั้นหน้า Vercel (เช่น CDN ของตัวเอง) ซึ่งต้องข้ามค่าตามจำนวนชั้นที่ไว้ใจ
