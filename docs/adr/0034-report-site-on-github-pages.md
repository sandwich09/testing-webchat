# 0034: หน้ารายงานเป็น static site บน GitHub Pages

> สถานะ: อนุมัติ · วันที่: 2026-11-20

## บริบท

ผู้ตรวจต้องการภาพรวมของระบบที่อ่านตามลำดับได้ในลิงก์เดียว: วิธีลอง ฟีเจอร์ architecture และผลทดสอบ เอกสารใน `docs/` ละเอียดพอสำหรับผู้พัฒนา แต่ยาวและกระจายหลายไฟล์เกินไปสำหรับการอ่านรอบแรก หน้านี้ต้องเปิดได้โดยไม่ต้องมีรหัสเข้าใช้ของ webchat และไม่ควรล่มตามแอป

## การตัดสินใจ

- หน้ารายงานเป็น HTML ไฟล์เดียวที่ [`report/index.html`](../../report/index.html) พร้อมรูปใน `report/img/` ไม่มีขั้น build และไม่มี dependency
- Workflow [`pages.yml`](../../.github/workflows/pages.yml) เผยแพร่โฟลเดอร์ `report/` ขึ้น GitHub Pages เมื่อมีการเปลี่ยนแปลงในโฟลเดอร์นี้บน `main` หรือเมื่อสั่งด้วยมือ action ทุกตัวตรึงด้วย SHA เช่นเดียวกับ [`ci.yml`](../../.github/workflows/ci.yml)
- Workflow นี้แยกจาก CI ของแอป ([ADR 0013](0013-ci-on-main-then-deploy-hook.md)): ไม่ build ไม่ test และไม่เกี่ยวกับ Deploy Hook ของ Vercel
- เนื้อหาของหน้ารายงานสรุปจาก `docs/` เมื่อสองที่ไม่ตรงกัน ให้ถือ `docs/` เป็นหลัก ([ADR 0001](0001-docs-as-source-of-truth.md))
- รูปในหน้ารายงานต้องไม่มีชื่อ รูปโปรไฟล์ หรือข้อมูลของบุคคลจริง

## ทางเลือกที่พิจารณา

- ใส่เป็น route ของแอปบน Vercel: ต้องยกเว้นจากรหัสเข้าใช้และ CSP ของแอป และหน้ารายงานจะล่มเมื่อแอปล่ม
- ตั้ง Pages ให้เผยแพร่โฟลเดอร์ `docs/`: เอกสาร Markdown ทั้งหมดจะถูกเผยแพร่ไปด้วย
- Branch `gh-pages`: ไม่ต้องมี workflow แต่ต้อง push branch แยกทุกครั้งที่แก้ และเนื้อหาไม่ผ่าน pull request
- ใช้ framework ทำเอกสาร: ได้ระบบค้นหาและ Markdown แต่เพิ่ม dependency และขั้น build สำหรับหน้าจำนวนน้อย

## ผลที่ตามมา

- ต้องตั้งค่า Pages ของ repository ให้ Source เป็น "GitHub Actions" หนึ่งครั้ง ก่อนตั้งค่า workflow จะล้ม
- หน้ารายงานเป็นสาธารณะ รหัสเข้าใช้ของ webchat ไม่อยู่ในหน้านี้
- `report/` อยู่ใน `.prettierignore` เพราะเป็น HTML ไฟล์เดียวที่ฝังฟอนต์
- ตัวเลขในหน้ารายงานเขียนด้วยมือและระบุ commit ที่นับไว้ท้ายหน้า เมื่อผลทดสอบเปลี่ยนต้องแก้เอง

## จะทบทวนเมื่อ

- หน้ารายงานมีเนื้อหามากจนไฟล์เดียวดูแลยาก
- ต้องการให้ตัวเลขผลทดสอบอัปเดตเองจาก CI
