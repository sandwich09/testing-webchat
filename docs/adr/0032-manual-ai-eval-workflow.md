# 0032: รันชุดคำถามวัดคุณภาพ AI ด้วย workflow ที่สั่งด้วยมือ

> สถานะ: อนุมัติ · วันที่: 2026-11-19

## บริบท

ชุดคำถามวัดคุณภาพ (`pnpm ai:eval`, [ai-prompt ข้อ 8](../specs/ai-prompt.md)) เรียก Claude จริงและมีค่าใช้จ่าย จึงไม่อยู่ใน CI ([ADR 0012](0012-testing-with-fakes-and-stubs.md)) และต้องรันบนเครื่องที่มี API key เจ้าของงานต้องการผลของชุดนี้ใน [test report](../qa/test-report.md) แต่ไม่สะดวกรันในเครื่อง และ key ไม่ควรผ่านแชทหรือเก็บไว้ในที่ที่คำสั่งอื่นอ่านได้

## การตัดสินใจ

1. เพิ่ม workflow แยก [`ai-eval.yml`](../../.github/workflows/ai-eval.yml) ที่เริ่มได้ทางเดียวคือ `workflow_dispatch` ไม่มี trigger จาก push, pull request หรือ schedule
2. มี input `confirm` เป็น boolean ค่าเริ่มต้น `false` ถ้าไม่ติ๊ก รอบนั้นจบโดยไม่เรียกอะไรและไม่อ่าน key ต้องติ๊กเองทุกครั้งที่จะรันจริง
3. Key อยู่ใน secret ของ repo ชื่อ `ANTHROPIC_API_KEY_EVAL` แยกจาก key ของ production
4. ก่อนเรียกที่มีค่าใช้จ่าย งาน `preflight` ตรวจ key ด้วย `GET /v1/models?limit=1` ซึ่งไม่คิดเงิน ถ้าได้ 401 (key หมดอายุหรือถูกยกเลิก) รอบนั้นล้มพร้อมข้อความบอกให้สร้าง key ใหม่และแก้ secret ถ้าไม่มี secret หรือได้สถานะอื่นก็ล้มพร้อมเหตุผลเช่นกัน
5. งาน `eval` รันทุกโมเดลที่หน้าตั้งค่าให้เลือก (`AI_MODEL_IDS`) ทีละโมเดล โมเดลหนึ่งล้มไม่หยุดโมเดลอื่น ไฟล์ผล `docs/qa/ai-quality-<วันที่>-<โมเดล>.md` เก็บเป็น artifact 30 วัน
6. [`e2e/workflows.unit.ts`](../../e2e/workflows.unit.ts) ยืนยันสี่ข้อ: เริ่มด้วยมือเท่านั้น, `confirm` เริ่มต้นเป็น `false`, งาน `eval` รอผลของ `preflight` และรายการโมเดลตรงกับ `AI_MODEL_IDS`

## ทางเลือกที่พิจารณา

- รันในเครื่องของเจ้าของงาน: key ไม่ออกจากเครื่อง แต่เจ้าของงานไม่สะดวก
- ใส่ key เป็น environment variable ของสภาพแวดล้อมพัฒนา: ทุกคำสั่งในสภาพแวดล้อมนั้นอ่าน key ได้
- ใส่ชุดคำถามในงานของ CI ปกติ: เสียเงินทุก push และผลของโมเดลไม่นิ่งพอจะใช้ตัดสินว่า build ผ่าน

## ผลที่ตามมา

- หนึ่งรอบเรียก Claude 51 ครั้งต่อโมเดลสำหรับตอบแชท ตัวคัดกรองหัวข้อ 24 ครั้ง และอ่าน PDF หนึ่งครั้ง รวมสามโมเดลประมาณ 3 ถึง 8 ดอลลาร์ตามตารางราคาใน `PRICE_TABLE` (ค่าประมาณ ยังไม่ได้วัดจริง)
- Log ของรอบมีรหัสข้อ ผล เวลา และค่าใช้จ่าย ไม่มีข้อความคำถามหรือคำตอบ ไฟล์ผลใน artifact มีคำตอบของโมเดลต่อคำถามตัวอย่าง ไม่มีข้อมูลของผู้ใช้จริง
- Workflow ที่สั่งด้วยมือรันได้เฉพาะผู้มีสิทธิ์เขียน repo และ fork อ่าน secret ไม่ได้
- เมื่อเพิ่มหรือถอดโมเดลใน `AI_MODEL_IDS` ต้องแก้ matrix ของ workflow ด้วย ไม่อย่างนั้น unit test ล้ม
- ไฟล์ผลไม่ถูก commit เข้า repo เอง ผู้พัฒนานำตัวเลขไปใส่ใน test report

## จะทบทวนเมื่อ

- ต้องการรันชุดคำถามเป็นประจำ หรือเทียบผลระหว่างรุ่นของ prompt
- ผู้ให้บริการเปลี่ยนวิธีตรวจ key หรือคิดเงินกับการเรียก `GET /v1/models`
