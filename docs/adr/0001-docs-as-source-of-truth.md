# 0001: เอกสารเป็น source of truth

> สถานะ: อนุมัติ · วันที่: 2026-11-18

## บริบท

ผู้พัฒนาทำงานเป็นรอบบนคลาวด์ ซึ่งไม่เก็บความจำข้ามรอบ ข้อตกลงที่อยู่แต่ในบทสนทนาจะหายเมื่อรอบนั้นจบ และผู้ตรวจต้องเห็นเหตุผลของการออกแบบ

## การตัดสินใจ

เขียนเอกสารใน `docs/` ก่อนเขียนโค้ด ฟีเจอร์ต้องมี spec และรายการในแผนก่อนสร้าง และโค้ดที่เปลี่ยนพฤติกรรมต้องแก้เอกสารใน commit เดียวกัน

## ทางเลือกที่พิจารณา

- เขียนเอกสารหลังโค้ดเสร็จ: ข้อตกลงหายระหว่างทาง และเอกสารมักไม่ตรงกับโค้ด
- ใช้แค่ README: ไม่พอสำหรับการตัดสินใจจำนวนมาก

## ผลที่ตามมา

มีงานเขียนเพิ่ม และต้องมีวินัยไม่ให้เอกสารบวม จึงมีกฎใน `docs/README.md` เช่น หนึ่งข้อเท็จจริงอยู่ที่เดียว และลบบันทึกงานเมื่องานจบ

## จะทบทวนเมื่อ

เอกสารเริ่มไม่ตรงกับโค้ดบ่อยจนไม่มีใครเชื่อ
