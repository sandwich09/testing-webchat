# 0020: ขอบเขตหัวข้อเป็นการตรวจแยกก่อนการตอบ

> สถานะ: อนุมัติ ข้อความปฏิเสธที่ตั้งเองถูกแทนที่โดย [0024](0024-scope-reductions.md) และการทักทายระบุเพิ่มใน [0026](0026-neutral-core-prompt-and-layered-settings.md) · วันที่: 2026-11-18
> ข้อความปฏิเสธที่ร้านตั้งเองถูกแทนด้วยประโยคคงที่ใน [ADR 0024](0024-scope-reductions.md)
> คำทักทาย ขอบคุณ และบอกลาสั้น ๆ ผ่านการคัดกรองตาม [ADR 0026](0026-neutral-core-prompt-and-layered-settings.md)

## บริบท

เจ้าของงานต้องการ guardrail สำหรับสาธิต: เมื่อเปิด AI คุยได้เฉพาะหัวข้อที่ร้านกำหนด และกฎนี้อยู่เหนือคำแนะนำของร้านกับคลังความรู้ คำสั่งระบบของการตอบแชทมีทั้งคลังความรู้ ประวัติแชท และคำแนะนำของร้าน ซึ่งล้วนดึงให้โมเดลตอบเรื่องของร้าน กฎหัวข้อที่อยู่ใน prompt เดียวกันจึงต้องแข่งกับข้อมูลเหล่านั้น และข้อความของลูกค้าอยู่ในบทสนทนาเดียวกับคำสั่ง

## การตัดสินใจ

เพิ่ม port `TopicGuard` ที่คัดกรองข้อความล่าสุดของลูกค้าด้วยการเรียกโมเดลแยกหนึ่งครั้ง ก่อนโหลดคลังความรู้และก่อนเรียกโมเดลตอบแชท ใช้ Claude Haiku 5.5 (`GUARD_MODEL`) เสมอ effort `low` structured output ที่มีแค่ `allowed` และ `matchedTopic` ไม่ stream retry หนึ่งครั้ง และไม่ใช้การสลับโมเดลสำรองฝั่ง server ซึ่ง Haiku 5.5 ไม่รองรับ ถูกกันแล้วส่งข้อความปฏิเสธที่ร้านตั้งไว้โดยไม่เรียกโมเดลตอบแชท การคัดกรองที่ล้มเหลวทุกแบบปิดแบบปลอดภัย: ไม่ส่งอะไรและขึ้นรอแอดมิน คำสั่งระบบของการตอบแชทยังได้รายการหัวข้อเป็นชั้นที่สอง และผลนอกเรื่องจากโมเดลตอบแชทถูกถือเป็นการกันแบบเดียวกัน รายละเอียดอยู่ใน [topic-guard](../specs/topic-guard.md)

## ทางเลือกที่พิจารณา

- กฎใน prompt ของการตอบแชทอย่างเดียว: ไม่มีจุดตัดสินที่แยกออกมาให้ backend ใช้ ไม่มีผลที่ตรวจด้วย schema ได้ และกฎต้องแข่งกับคลังความรู้และประวัติในคำขอเดียวกัน จึงยังใช้เป็นชั้นที่สองเท่านั้น
- รายการคำต้องห้าม: หัวข้ออย่างมุกตลกหรือมีมเขียนเป็นรายการคำไม่ได้ ข้อความต่อเนื่องเช่น "ขออีกมุก" ไม่มีคำของหัวข้อ และเลี่ยงได้ง่ายด้วยการสะกดต่าง
- ให้โมเดลตอบแชทตัดสินเองว่านอกเรื่อง (moderation โดยโมเดลเดียว): ต้องเรียกโมเดลตัวใหญ่ที่มีคลังความรู้ทั้งคลังทุกครั้งแม้ข้อความจะถูกกัน ซึ่งแพงกว่า และการตัดสินปนกับการเขียนคำตอบ

## ผลที่ตามมา

- ทุกข้อความที่ AI ตอบขณะขอบเขตหัวข้อเปิดมีการเรียกโมเดลเล็กเพิ่มหนึ่งครั้ง เวลาตอบเพิ่มราวหนึ่งวินาทีต่อข้อความ และต้นทุนของการคัดกรองนับรวมในงบต่อวันและแสดงเป็นแถวแยกในค่าใช้จ่าย AI
- ข้อความที่ถูกกันไม่เรียกโมเดลตอบแชท จึงถูกกว่าการให้โมเดลตัวใหญ่ปฏิเสธเอง
- เวลาแย่ที่สุดของหนึ่งรอบยาวขึ้นตาม `GUARD_TIMEOUT_MS` ต้องอยู่ในเพดานเวลาของงานหลังตอบ
- ตัวคัดกรองที่ใช้ prompt ไม่ปิดสนิท ระบบจึงระบุเป็นการป้องกันหลายชั้น ไม่ใช่การรับประกัน
- มี port ใหม่ ตัวปลอม ชุดทดสอบของ port, adapter และการแยกชนิดคำขอใน stub

## จะทบทวนเมื่อ

อัตราการกันผิดหรือการหลุดจากชุดคำถามวัดคุณภาพสูงเกินรับได้ เวลาตอบที่เพิ่มขึ้นเป็นปัญหาของผู้ใช้ หรือผู้ให้บริการมีบริการคัดกรองหัวข้อที่ตรวจได้แน่นอนกว่า
