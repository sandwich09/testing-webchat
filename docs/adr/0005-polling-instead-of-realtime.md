# 0005: Polling แทน real-time

> สถานะ: อนุมัติ · วันที่: 2026-11-18

## บริบท

หน้าแชทต้องเห็นข้อความใหม่โดยไม่ต้อง refresh แต่ Vercel ไม่มี process ค้างสำหรับ WebSocket

## การตัดสินใจ

หน้าเว็บ polling ทุก 2 วินาทีด้วย cursor (`seq` ของข้อความ) ขอย้อนหลังเล็กน้อยและตัดรายการซ้ำด้วย id หยุดเมื่อแท็บถูกซ่อน และถ่วงเวลาเมื่อล้มเหลว

## ทางเลือกที่พิจารณา

- บริการ real-time ภายนอก (Pusher, Ably): เพิ่มบริการและ key อีกชุด
- Server-Sent Events: บน serverless ต้องมีที่กระจายเหตุการณ์ข้าม function เพิ่ม
- Supabase Realtime: ผูกกับผู้ให้บริการฐานข้อมูล

## ผลที่ตามมา

ง่ายและทำงานเหมือนกันทุกสภาพแวดล้อม ข้อความใหม่ช้าได้ถึงราว 2 วินาที และมีคำขอถี่ต่อแท็บที่เปิดอยู่

## จะทบทวนเมื่อ

มีแอดมินหลายสิบคนเปิดพร้อมกัน หรือต้องการแสดงสถานะกำลังพิมพ์ของอีกฝั่ง
