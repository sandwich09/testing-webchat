# 0003: โครงสร้างโค้ดแบบ hexagonal

> สถานะ: อนุมัติ · วันที่: 2026-11-18

## บริบท

ระบบต่อกับบริการภายนอกหลายตัว (LINE, Claude, ฐานข้อมูล, ที่เก็บไฟล์) กฎทางธุรกิจมีกรณีขอบมาก เช่น การกันซ้ำ การรวมข้อความ และ kill switch ซึ่งทดสอบกับของจริงได้ยากและเสียเงิน

## การตัดสินใจ

แกนกลาง (`core/`) ประกอบด้วย domain, ports และ use cases และห้าม import framework, ORM, SDK และ `process.env` ของจริงเป็น adapter ที่ประกอบเข้ามาใน `composition/` ที่เดียว และ lint บังคับทิศทางการ import เส้นทางที่อ่านอย่างเดียวใช้ use case บาง ๆ เรียก repository ตรง

## ทางเลือกที่พิจารณา

- เขียนตรงใน route handler: เร็วตอนเริ่ม แต่ทดสอบกรณีขอบไม่ได้โดยไม่ต่อของจริง
- ทำครบทุกชั้นทุกเส้นทาง: พิธีกรรมมากเกินสำหรับหน้าที่แค่อ่านข้อมูล

## ผลที่ตามมา

Use case ทั้งหมดทดสอบได้ด้วย adapter ปลอม และเปลี่ยนผู้ให้บริการได้โดยไม่แตะแกนกลาง แลกกับไฟล์ที่มากขึ้นและ mapper ระหว่าง Prisma กับ domain

## จะทบทวนเมื่อ

ชั้นใดชั้นหนึ่งกลายเป็นทางผ่านเปล่า ๆ ในทุก use case
